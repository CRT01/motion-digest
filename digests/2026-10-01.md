# 动效简报 · 2026-10-01

本窗口四件事：`SvaraNova/skills` 的 `web-motion` 把「先选工具、再用 token」写成可安装 skill；`awesome-ai-motion` 用 637 张效果卡给产品演示与滚动叙事挑动作；Motion 补到 **13.4.7**（ViewTimeline 滚动加速 + `AnimatePresence` wait 丢子）；`fluid-functionalism` 把弹簧档位、更快退场和流体悬停写进 shadcn 组件库。盯着的 Emil skills、AlphaXe、mblode、animations.dev、优设猎人（除已收录的 Kobra）本窗口没有新的产品级增量。

### [SvaraNova web-motion](https://github.com/SvaraNova/skills/tree/main/frontend/web-motion)

**类型：** skill

**是什么。** `SvaraNova/skills` 是 9 月 30 日新开的 Agent Skills 包，其中 `frontend/web-motion` 专做产品界面动效：微交互、菜单/模态进出、列表增删、路由与 View Transition、滚动揭示、骨架屏。skill 开篇就是**选型表**——能 CSS `transition` / `@starting-style` / WAAPI / View Transitions / `animation-timeline: view()` 就别上库；只有退出卸载、共享布局、手势弹簧才用 Motion，长叙事滚动才用 GSAP。附带完整 CSS motion token 表（`--dur-micro/ui/large` 与对应 exit ≈70%）、组件 recipes（按钮、popover、dialog、toast、accordion、FLIP、skeleton）以及 DevTools 性能 checklist。安装：把 `frontend/web-motion` 拷进 `~/.agents/skills/`（或各 agent 的 skills 目录）。

**何时用。** Agent 要给真实网站/应用加动效，又容易一上来就 `npm i motion` 或乱写时长时。

**可带走的一点。** **退出比进入短约 30%，用 ease-in；进入用 ease-out；弹簧过冲只留给小控件。** 时长阶梯：微交互 100–150ms、UI 200–300ms、大面 400–600ms；用户会反复触发的动作不要超过 300ms。stagger 每项 30–50ms，总 stagger 封顶约 300ms。

### [awesome-ai-motion](https://github.com/gongnyang/awesome-ai-motion)

**类型：** skill / 库

**是什么。** `gongnyang/awesome-ai-motion`（同日发布）是给 Agent 读的动作图鉴：637 张效果卡、128 段参考片、11 条配方、7 条交付路线（含 **Product UI Demo**、Scroll Deck）。每张卡有默认时长/缓动、过用警告和 Claude/Codex 提示词；`SKILL.md` 要求先写「这一幕要让人明白什么」，再查决策表，最后用 `node scripts/render.mjs` 只换文案出片。站点可慢放对比：https://gongnyang.github.io/awesome-ai-motion/ 。装 skill：`ln -s` 仓库到 `~/.claude/skills/awesome-ai-motion`。

**何时用。** 做产品 UI 演示片、滚动叙事、说明视频的动效选型，需要可复现的默认参数而不是让模型瞎编缓动时。

**可带走的一点。** **产品演示配方固定四拍：打字输入 → 光标点击发送 → 回答流式出现 → 关键点放大 callout；输入未完成前不要点发送，且输入光标与 callout 不要同色抢焦点。** 通用规则：一幕一个主动作；优先 `transform`/`opacity`；完成态至少 hold 约 0.6s 再切走。

### [Motion 13.4.7](https://github.com/motiondivision/motion/releases/tag/v13.4.7)

**类型：** 库

**是什么。** 继昨日简报的 13.4.5 之后，Motion 在 9 月 29–30 日又发了 **13.4.6** 与 **13.4.7**。13.4.6：`AnimatePresence` 的 `mode="wait"` 在 React transition 期间若 exit 刚好结束，不再把新进来的子节点丢掉。13.4.7：更多 `scroll`/`useScroll` 的 `offset` 走 `ViewTimeline` 硬件加速；主线程与 ViewTimeline 路径的 offset 行为对齐；去掉基于 ScrollTimeline/ViewTimeline observer 的跟踪，改回主线程 scroll 跟踪；加速版 `useTransform` 现在会正确 clamp。changelog：https://motion.dev/changelog?lib=motion#13-4-7

**何时用。** 项目已在用 `motion/react` 的滚动进度、硬件加速 transform，或用 `AnimatePresence mode="wait"` 做路由/步骤切换时。

**可带走的一点。** **升级到 ≥13.4.7：修 wait 模式丢子 + 滚动 offset 加速与一致性。** 若你依赖旧的 timeline observer 行为，先在真机核对 `useScroll` 的 progress 曲线再合入。

### [Fluid Functionalism 动效体系](https://github.com/mickadesign/fluid-functionalism/blob/main/motion-guidelines.md)

**类型：** 组件 / 规范

**是什么。** `mickadesign/fluid-functionalism` 是一套带「满意悬停」的 shadcn registry（Radix / Base UI 双味）。动效不是装饰：三档弹簧 `spring.fast/moderate/slow`（约 0.08 / 0.16 / 0.24s），**每档自带更快一档的 `.exit` tween**（0.06 / 0.12 / 0.16s），杜绝手写 exit duration 漂移；`useFluidHover` 让列表只亮一块跟随最近行的高亮，缝隙里也不灭；字重变化用 ghost span + `opsz` 轴，避免选中加粗挤乱排版。规范写在 `motion-guidelines.md`，组件可 `npx shadcn@latest add @fluid/...`，也可 `npx skills add mickadesign/fluid-functionalism`。站点：https://www.fluidfunctionalism.com

**何时用。** 要在现有 shadcn 项目里统一弹簧档位与列表悬停手感，或抄一套「进场弹簧、退场更快 tween」的 token 时。

**可带走的一点。** **进场用弹簧 token，退场用同档 `.exit`（更快、无弹跳）；嵌套的测高折叠不要叠两层弹簧——外层在子级折叠引起的再测量上应 snap（`duration: 0`），否则会追着子级拖泥带水。** 能 `transform`/`opacity` 就别动 `top`/`left`/`width`/`height`，这样根上的 `MotionConfig reducedMotion="user"` 才能白送减动。
