# 动效简报 · 2026-10-05

周末窗口六件事：Figma Motion 把**动画样式**做成可发布到团队库的资产，并能直接导出 Lottie / dotLottie；`view-transitions` skill 把 View Transitions 讲成「截图形变」并列出五个静默失败点；`onboarding-motion` 把功能引导里的光标小场景写成一张锁死的节拍表；`motion-kit` 的 `motion-ui` 要求先读项目自己的动效规范，再用可中断弹簧；`add-animations` 给整站做双向滚动揭示，并附 Playwright 验收；Motion 跳到 **14.0.0**，但这是一次依赖收口，不是 API 大改。盯着的 Emil skills 本窗口新增了 `break-ui`（用最坏数据压测 UI，不属于动效，未收录）；mblode、AlphaXe、LottieFiles skill、gsap-skills、vercel-labs、remotion skills、animations.dev、Rive、优设没有新的产品级动效增量。

### [Figma Motion：自定义动画样式 + Lottie 导出](https://www.figma.com/release-notes/)

**类型：** 规范 / 交付（Figma Motion）

**是什么。** 9 月 30 日 Figma Motion（仍是 open beta）上线了四项能力。其中对产品团队最重要的是**自定义动画样式**：把自定义缓动、时长和其他「由变量驱动」的属性存成一个样式，可以把多个样式组合成一个复合模式，再**发布到团队库**，让所有文件引用同一套动效，并能通过 MCP 或 Skills 让 Figma agent 和编码 Agent 自动套用。插件 API（[Update 140](https://developers.figma.com/docs/plugins/updates/2026/09/30/version-1-update-140/)）同步开放：`CustomAnimationStyle`、`figma.createCustomAnimationStyle()`、`addAnimationEntryAsync()`，`applyAnimationStyle()` 也支持 `{ type: "CUSTOM" }`。另外三项：时间轴可以拖入音频，并随 MP4/WebM 一起导出；文本可以按字、词、行做动画，且仍可编辑；顶层 frame 可以直接导出 **Lottie**（裸 JSON，一个文件一段动画）或 **dotLottie**（压缩包，可以打包多段动画和字体、图片）。[导出文档](https://help.figma.com/hc/en-us/articles/41307983648407-Export-animations-from-Figma)写明了限制：shader 和角向渐变会被压成静态图，视频不支持；投影、噪点、玻璃效果只取第一帧，不随动画变化。

**何时用。** 团队的时长/曲线 token 一直只活在文档里，希望设计稿、交付文件和 Agent 生成的代码用同一个来源时；或者想把 Figma 里的状态动画直接交给前端，用 Lottie 播放。

**可带走的一点。** **先把 3–5 个核心动效（进场、退场、按压、面板）做成库样式并绑定时长/缓动变量，再让 Agent 通过 MCP 套用，不要让它每次各自写一个数字。** 要导出 Lottie 的画面只动位置、透明度、尺寸、圆角、描边宽度和纯色；避开角向渐变、shader 和动态投影。LottieFiles 插件路径的[支持表](https://docs.lottiefiles.com/en/integrations/figma/04_figma-to-lottie/figma-motion-export)也提醒：弹簧缓动是按时间采样导出的，导出后要在真实播放器里复核。

### [view-transitions](https://github.com/adelpro/view-transitions)

**类型：** skill

**是什么。** `adelpro/view-transitions`（10 月 3 日）是一个专讲 Web View Transitions 和共享元素形变的构建型 skill。它的核心判断是：view transition 是**截图形变**，不是属性动画。浏览器先给变化前后的元素各拍一张快照，再插值位置、尺寸、圆角和像素，所以开发者不需要测量任何东西。它按技术栈分三条路：React ≥ 19.3 用 `<ViewTransition>`；其他 JS 环境用经过特性检测的 `document.startViewTransition`；无 JS 的多页站用 `@view-transition { navigation: auto }`。按意图分六种场景：卡片变详情页、列表重排、主题圆形揭开、从按钮长出的弹窗、跨文档导航、骨架屏变内容，每种都有可点击的零依赖 `assets/demo.html`。它的立场是：很多时候诚实的答案是「这里不加过渡」，过渡只回答「从哪来 / 去哪了 / 变了没」这三个问题之一。不覆盖 React Native、Expo 和 Android。

**何时用。** 要做路由切换、卡片展开、列表排序动画，或者遇到「`view-transition-name` 写了却不动」的时候。

**可带走的一点。** 每个过渡都要带上这两段：`::view-transition { pointer-events: none; }`（否则动画期间覆盖层会吞掉快速的第二次点击），以及 `prefers-reduced-motion` 下把 `::view-transition-old/new/group(*)` 的时长设为 0（浏览器和 React **都不会自动处理**）。另有三个硬规则：同一个 `view-transition-name` 在全应用里只能出现一次，重名时过渡会被**静默跳过**；按钮弹出的弹窗必须在同一次过渡里先把名字交出去（`none` → dialog `share`）；页面级形变用 250–400ms，其余仍然守住 300ms 以内。

### [onboarding-motion](https://github.com/nurdkub/onboarding-motion-skill)

**类型：** skill / 规范

**是什么。** `nurdkub/onboarding-motion-skill`（俄文，10 月 5 日发布 v1.2.0）基于 Square 设计系统，做 Telegram 式的「功能引导小场景」：提示气泡里放一张界面缩略图，一个光标自己演示新操作，最后停在结果画面上。关键设计是：作者**只写剧本**（`click` / `type` / `point` / `react`），节拍、曲线、按压反馈、最终帧和循环都由引擎锁死，所以不管谁来写，出来的场景都一样。场景里只允许使用真实的设计系统组件，不画简化版 mockup。默认交付的是**一个动画 SVG**，能直接放进 Figma、文档和邮件，并作为参照交给前端。`prefers-reduced-motion` 下只显示最终帧，不显示光标。`references/timing.md` 是一份可以照搬的节拍表。

**何时用。** 给产品新功能做悬停提示里的小演示，希望多个作者产出一致、节奏不被各自调乱时。

**可带走的一点。** 三条曲线按角色固定：进场 `cubic-bezier(0.16, 1, 0.3, 1)`，退场 `cubic-bezier(0.7, 0, 0.84, 0)`，光标移动 `cubic-bezier(0.65, 0, 0.35, 1)`。一次 `click` 的节拍 = 移动 600 → 悬停 200 → 按下 100 → 响应 450，共 1350ms。光标移动固定 600ms，**不按距离折算**，节奏反而更稳。状态在**松开**那一刻才变化。整个循环目标 8s、上限 9s，用户操作最多 5 步；超出就拆成两个提示。

### [motion-kit · motion-ui](https://github.com/triippiing/motion-kit/tree/main/skills/motion-ui)

**类型：** skill / 库

**是什么。** `triippiing/motion-kit` 有三个 Claude Code skill。其中两个做按节拍渲染的宣传视频，不属于本栏目；值得看的是第三个 `motion-ui`，专管真实产品 UI 里的指示条、开关、进度条、拖拽和可中断过渡。它的第一步是**项目自己的动效规则优先**：先 grep `--dur` / `--ease` / `--motion` 这类 token、找 `motion` / `handoff` 目录、找已有的 reduced-motion 辅助函数，把适用的规则引用进方案。如果规范禁止过冲，所有弹簧都用 ζ = 1。时长来自 token，用 `Springs.fromSettle(tokenSeconds, zeta)` 换算。常规 UI 时刻（下拉、弹窗、toast、tab）优先查 Jakub Antalik 的 transitions.dev 目录（32 种），但要把它的数值映射到项目 token 上，不能直接引入它的 `_root.css`。需要可中断、带速度的场景才用自带的闭式解弹簧 `springs.js`。

**何时用。** 有人说「把这个 tab 指示条做得更弹一点」，而项目里已经有动效 token 或交付文档时。

**可带走的一点。** **CSS transition 中途改目标时会丢掉速度；需要中途改目标的值，用 `Springs.live({...}).set(target)`，它会同时保留位置和速度。** 拖拽松手用 `fling(x, v, snap)` 把甩出的速度带进去。容器形变中替换内容的配方：旧内容以约 0.4× 容器收敛时间快速退场，新内容在约 0.15× 收敛时间后进场，透明度未满时 blur ≤ 8px；**不要**在同一个框里让两段满尺寸文字同时交叉淡入淡出。没有规范时，位置类默认 ζ = 1，只有俏皮的缩放弹出才用 ≤ 0.85。

### [add-animations](https://github.com/mrrobotbuilder/add-animations)

**类型：** skill

**是什么。** `mrrobotbuilder/add-animations`（10 月 4 日）给**整个网站**做一遍动效，并在真实浏览器里证明没弄坏东西。它来自一次 Next.js 16 作品集站的四阶段实战。流程是：先读站点和**每一行文案**，测 Lighthouse 基线，再把「段落 → 它要说的一句话 → 对应的一个动作」列成表，最多问站主四个问题，然后按成本从低到高分层构建：CSS 首屏入场 → GSAP ScrollTrigger 双向揭示（向下滚时升起，往回滚时从上方落下）→ 原生 CSS 滚动驱动层 → 和文案绑定的段落主角动效 → View Transitions 页面切换 → 控件反馈。附带 40 种风格目录，每种都写明何时用、何时跳过、怎么做、reduced-motion 下如何降级；还有两套 Playwright 检查（主页面往返滚动 + 全路由三种视口审计）。立场：动效跟随访客，没有暂停控件的自动动画不超过 5 秒（WCAG 2.2.2）；服务端渲染的就是最终页面。

**何时用。** 营销站或作品集要做一遍完整的滚动动效，又怕变成「全部 fade up 一次」的廉价感，或者怕弄坏键盘导航和性能时。

**可带走的一点。** **等待揭示的元素只用 opacity 隐藏，绝不要用 `visibility: hidden`（也就不要用 GSAP 的 `autoAlpha`）**：它会把元素移出 Tab 顺序和无障碍树，键盘用户会直接跳到页脚。要补一个 `focusin` 监听，让元素被聚焦时立即显示。批量 stagger 间隔 0.08s、总长封顶 0.4s。会缩放或乱码的文字要 `overflow-x: clip`，并在延迟加载 web 字体的条件下再测一次页面宽度：回退字体更宽，可能把页面撑出横向滚动。

### [Motion 13.5.1 → 14.0.0](https://github.com/motiondivision/motion/blob/main/CHANGELOG.md)

**类型：** 库

**是什么。** Motion 在 10 月 2 日连发两版。**13.5.1** 是修复版：`inherit={false}` 现在确实不再继承父级动画；兄弟节点未挂载时 `sortNodePosition` 不再抛错；`readSVGValue` 在计算样式为空时回退读取属性；`svgEffect` 不再把 transform/origin 写成属性；还临时恢复了内部的 `observeTimeline` API，以兼容 `framer-motion` 13.0–13.4。**14.0.0** 只做了一件事：移除这些兼容垫片，并把 `framer-motion`、`motion-dom`、`motion-utils` 之间的内部依赖**锁定到精确版本**，以后移除内部 API 时不会再出现跨包不兼容。对公开 API 来说，这不是一次破坏性改版。

**何时用。** 准备从 13.5.0 升级，或者项目里同时存在旧版 `framer-motion` 和新版 `motion` 时。

**可带走的一点。** **只用公开 API 的项目可以直接升到 14；凡是从 `motion-dom` 引用了内部导出（例如 `observeTimeline`）的代码，先改掉再升。** 如果用到了 `inherit={false}` 或 SVG 动画，13.5.1 的修复值得马上拿到。
