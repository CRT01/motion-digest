# 动效简报 · 2026-10-09

今天五件事。最值得收藏的是 `motion-guide-skill`：一套「先决定要不要动」的产品动效决策层，114 个命名模式，明确允许推荐 `no motion`。`fluid-design` 把流体界面压成 10 条物理原则（弹簧、可打断、速度继承、橡皮筋边界）。Scott Tolinski 的 `css-motion-systems` 专注纯 CSS：`linear()` 缓动 token、独立 transform 属性、View Transitions。`micro-interactions-skill` 是跨端微交互百科，带时长表、弹簧表和交付审计卡。最后是 `iart-ai/web-animation-skills`，尤其是 `60fps-animation` 与 `micro-interaction` 两份——把「只动 transform/opacity」和 FLIP/`height: auto` 写成可直接执行的规则。盯着的 Emil skills、AlphaXe、Motion 正式版、LottieFiles skill、gsap-skills、ai-kit 本窗口没有新发布；Motion 主分支有未发布的 layout-in-drag / AnimatePresence popLayout 等修，等 changelog 再报；mblode 本周更新是 PR 工具链，与动效无关。

### [motion-guide（产品安全的动效决策 Skill）](https://github.com/JarvixGaby/motion-guide-skill)

**类型：** skill / 设计哲学

**是什么。** `JarvixGaby/motion-guide-skill`（MIT）不是组件库，而是给 agent 用的动效决策层：先判定 `use motion` / `reduce motion` / `no motion`，再选一个命名模式，并带上时长、缓动、无障碍、减少动态效果与性能约束。安装是 `npx skills add JarvixGaby/motion-guide-skill`。它收录 114 个实用 UI 模式（加载、反馈、转场、空态、确认、数据、滚动、引导等）外加一套创意包（3D / shader / 粒子），但强调创意动效也必须有产品意图。配套参考 `references/motion-database.md` 给每个模式写了「何时用 / 何时不用 / 风险 / 替代」。审查模式要求按 Keep / Reduce / Remove / Fix 分类，专门抓假进度、完成前庆祝、大列表逐项 stagger、为小效果引入重库这类廉价感。

**何时用。** 跟 agent 做产品界面动效、审查 PR 里的动画 diff，或需要一份「什么时候根本不该动」的门禁。

**可带走的一点。** **先定决策再写代码：`use` / `reduce` / `no`。** 高频路由默认只做透明度淡入淡出；大列表 stagger 按「前几项封顶」而不是按结果数线性加长；AI/工具活动用 `tool-call-timeline` 做可审计状态，`ai-thinking-orb` 只能当氛围，不能替代真实步骤。

### [fluid-design（流体界面的十条物理原则）](https://github.com/kemiljk/fluid-design)

**类型：** skill / 设计哲学

**是什么。** `kemiljk/fluid-design`（MIT）是一份把「手感」拆成 10 条原则的 agent skill，安装 `npx skills add kemiljk/fluid-design`。核心不是又一套组件，而是：弹簧代替固定时长、动画必须可打断、直接操纵优先于按钮间接控制、松手时把手势速度传给下一段弹簧、共享元素保持空间上下文、按输入方式（hover / coarse pointer）适配、布局变化用 layout/FLIP 而不是瞬移、边界用渐进阻力（橡皮筋）、多元素用编排 stagger、以及尊重 `prefers-reduced-motion`。每条原则都给了 Framer Motion / React Spring / 原生 JS 示例，并附调参区间（如 stiffness 200–400、damping 20–30）。

**何时用。** 做抽屉、卡片堆、可重排列表、跟手拖拽这类「要有物理感」的产品控件，或要审查现有动效为什么「僵」。

**可带走的一点。** **松手测手感：快甩应略过冲再回落，慢放应轻轻滑入；两种手感一样，说明没继承 velocity。** 可打断比「更短的时长」更重要——能在任意时刻改目标的 400ms 弹簧，体感往往快过锁死输入的 200ms。

### [css-motion-systems（纯 CSS 动效体系 + linear() token）](https://github.com/stolinski/motion-skills)

**类型：** skill

**是什么。** `stolinski/motion-skills` 里的 `css-motion-systems`（Scott Tolinski）专做网页产品动效的 CSS 侧：何时用 transition / keyframes / WAAPI / View Transitions，以及 `translate`/`rotate`/`scale` 独立属性 vs `transform` 简写、`translate3d` 何时才值得。它把 `linear()` 缓动当成品牌签名工具——用 4–8 个控制点做出类似弹簧的 settle，而不是默认 `ease`。附带 `MOTION_TOKENS.css`（quick 140ms / normal 220ms / structural 320ms / route 420ms，外加 enter/exit/emphasis 与 `linear()` settle），View Transitions 同文档与跨文档配方，以及交付前的审查清单。产出合同固定五段：Intent → Motion Spec → Implementation → Accessibility Fallback → QA。

**何时用。** 想少引 JS 动效库、用 CSS 变量统一全站动效，或要认真做同页/跨页 View Transitions。

**可带走的一点。** **微交互 120–180ms，组件 180–260ms，结构/路由 240–420ms；退场普遍快于进场。** `linear()` 适合「有个性的 settle」，点数保持可读；不要把 `translate3d` 当万能 GPU 魔法，真有 3D 或测出瓶颈再用。

### [micro-interactions-skill（跨端微交互架构 Skill）](https://github.com/solinkz/micro-interactions-skill)

**类型：** skill

**是什么。** `solinkz/micro-interactions-skill`（MIT）按 Dan Saffer 的 Trigger → Rules → Feedback → Loops 框架组织，覆盖 Web / iOS / Android / React Native。它给了一张通用时长表（Instant 0–50ms 到 Dramatic 500–1000ms，退场约为进场的 60–75%）、10 条 cubic-bezier 与弹簧预设表（Gentle / Default / Snappy / Bouncy / Stiff），以及按钮、开关、下拉刷新、滑动操作、底栏、表单校验、骨架屏、Toast、Modal、共享元素、Tab 指示条等模式的「状态剧本」。还有 10 维审计记分卡（反馈、时长、缓动、一致性、性能、无障碍等），低于 4 分要给具体修法。实现顺序强调：先做无动画也能用的版本，再渐进加动效；工具选型是 CSS transition → keyframes → 库。

**何时用。** 需要一份跨平台微交互手册，或要审计已上线界面「哪里该有反馈却没有」。

**可带走的一点。** **功能动效不超过约 400ms；只动 `transform` / `opacity`（必要时谨慎用 `filter`/`clip-path`）。** 交付前跑一遍决策清单：高频操作要克制、纯装饰默认跳过、第 100 次还会烦的就降强度或删掉。

### [web-animation-skills（60fps 与微交互菜谱包）](https://github.com/iart-ai/web-animation-skills)

**类型：** skill

**是什么。** `iart-ai/web-animation-skills`（MIT，`npx skills add iart-ai/web-animation-skills`）是一组可分装的网页动效 skill：`gsap-web`、`60fps-animation`、`page-transition-animation`、`accessible-animation`、`micro-interaction`、`lottie-animation` 等。其中最硬核的是 `60fps-animation`：把昂贵属性映射到便宜等价物（宽高→scale/FLIP，阴影→伪元素 opacity，`height: auto`→`grid 0fr→1fr` 或 `interpolate-size`），讲清读写批处理防 layout thrashing，以及用 Performance 面板确认「每帧没有 Layout/Paint」。`micro-interaction` 则覆盖 `whileTap` 弹簧、`AnimatePresence`、`layout`/`layoutId`，以及纯 CSS 的 `@starting-style` + `transition-behavior: allow-discrete` 进出场。两份 skill 都要求可独立打开的单 HTML 交付，并用 `?t=` / `?state=` 冻结截图做验收。

**何时用。** 动画卡顿要查因，或要给 agent 一份「能截图验收」的微交互/性能菜谱。

**可带走的一点。** **卡顿优先查有没有在动 layout 属性；修好后用 Performance 看紫色 Layout / 绿色 Paint 是否消失。** `height: auto` 跨浏览器稳妥方案仍是外层 `grid-template-rows: 0fr → 1fr`，内层 `overflow: hidden; min-height: 0`。
