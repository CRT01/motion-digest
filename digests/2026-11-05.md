# 2026-11-05 动效日报

今日五件：Emil 新 skill `/choreograph` 把多元素关系写成可执行合同；Motion 14.9.1 修 AnimatePresence 退出卡死；UltraUI 的 stagger-orchestration 用总时长预算替代按项累加；unslop-anything 把「飞行入场 / transition-all」写进可扫描的反廉价清单；Android M3E×Nav3 技能包把 MotionScheme 弹簧与共享轴转场钉进主题。

### [choreograph · Emil 多元素编排 skill](https://github.com/emilkowalski/skills/tree/main/skills/choreograph)

**类型：** skill

**是什么。** Emil Kowalski 于 2026-11-04 推送 [`/choreograph`](https://github.com/emilkowalski/skills/blob/main/skills/choreograph/SKILL.md)（推文：[A new skill: /choreograph](https://x.com/emilkowalski/status/2117996960028450836)），安装：`npx skills add https://github.com/emilkowalski/skills --skill choreograph`。它不管单段缓动（那是 `animate`），也不管该不该动（那是 `find-animation-opportunities` / `remove-animations`）；只管**同一事件下多个元素的关系**：顺序、重叠、静止。硬规则包括：容器只做一次入场（面板滑入时内容已在）、高频/键盘触发 UI 禁止 stagger、禁止统一节拍的机械 stagger、编排不得挡住可点、序列必须扛得住打断。角色先拆成 Lead / Support / Decoration / Static；两两关系只选 Together / Overlap / Sequence / Carry。产品 UI 的 stagger 建议 **30–80ms、整组 ≲300ms**，长列表只 stagger 前几项。附 [`RECIPES.md`](https://github.com/emilkowalski/skills/blob/main/skills/choreograph/RECIPES.md)：CSS `--i` stagger、`delayChildren: stagger(...)`、`AnimatePresence mode="popLayout"`、方向感知步骤、以及「退出元素立刻离流、兄弟边淡边补位」。

**何时用。** 列表入场、容器内视图切换、多步流程、图标+背景+线条一起动，或感觉「各自很顺、合在一起像排队」。

**可带走的一点。** 先砍动的零件、尽量并行；只有阅读顺序、因果或物理先后才排队——好的序列读成一个手势，坏的读成队列。

### [Motion 14.9.1 · AnimatePresence 退出修复](https://github.com/motiondivision/motion/blob/main/CHANGELOG.md)

**类型：** 库

**是什么。** [motion@14.9.1](https://www.npmjs.com/package/motion)（2026-11-04）是补丁版：保证加速 transform 动画能正确收尾；修 `AnimatePresence` 在子节点**挂载时已处于 exiting** 时 `exit` 根本不启动；修打开的 `layoutId` 卡片切到另一项后 `exit` 卡住；并清理 WebKit 上加速动画残留。对上一条 choreograph 的 `popLayout` / 方向感知退出直接相关——退出合同写对了，库还得真的播出来。

**何时用。** 已在用 Motion 的列表删除、卡片/共享布局切换、快速连点切换路由，若出现「旧层挂住」或「退场不播」。

**可带走的一点。** 升到 14.9.1 后再测：子节点带稳定唯一 `key`；若仍异常，先查是否「挂载即 exiting」或 `layoutId` 抢占路径。

### [stagger-orchestration · 总时长预算的交错](https://github.com/AvnehSBhatia/UltraUI/tree/main/skills/primitives/stagger-orchestration)

**类型：** skill

**是什么。** [AvnehSBhatia/UltraUI](https://github.com/AvnehSBhatia/UltraUI)（147 个 UI skill）里的 [`stagger-orchestration`](https://github.com/AvnehSBhatia/UltraUI/blob/main/skills/primitives/stagger-orchestration/SKILL.md)：心智模型是**先定整组总预算，再除到各项**，而不是 `N × perItemDelay` 线性膨胀。GSAP 用 `stagger: { amount: 0.4 }` 代替 `{ each: 0.08 }`；网格支持 `from: "center"|"edges"`、`grid: [rows, cols]`。调参建议：固定项数时单项延迟 40–100ms；4–8 项总预算约 300–500ms；单次视口 stagger 不超过 8–12 项；总 stagger 别超过 800ms。反廉价规则与 Emil 同向：可变长度列表禁用固定 per-item、别对折线下元素 stagger、别在来回导航重复播同一组。安装入口见 skills.sh：`npx skills add https://github.com/avnehsbhatia/ultraui --skill stagger-orchestration`。

**何时用。** 卡片/导航/文案行级联入场、网格辐射/汇聚、标题→卡片→CTA 嵌套时间线，且列表长度不固定。

**可带走的一点。** 先写「整组要在 400ms 内结束」，再算 `perItemDelay = budget / (N - 1)`——20 项时用固定 80ms 会拖到 1.6s，像加载失败。

### [unslop-anything · 可扫描的反廉价（含动效章）](https://github.com/Pacheche/unslop-anything)

**类型：** skill / 设计哲学

**是什么。** 2026-11-04 公开的 Agent Skill：把「AI 默认堆出来的样子」拆成可审计类别，并配 `scripts/slop_scan.py`。UI 路径读 [`references/ui-signs.md`](https://github.com/Pacheche/unslop-anything/blob/main/references/ui-signs.md)；第 9 类 **Motion** 明确点名：非 live 表面的 `animate-pulse/ping/bounce`、`transition-all`、卡片 `hover:scale-105` / `-translate-y-1`、简单控件上的弹性过冲、入场全体飞入与按 index 永久 stagger、视差/滚动飘浮、动画 `width/height/top/left` 或大 blur、轮播硬切。工作流是 Detect（只出 slop level）或 Fix（方向 → 分 pass 改 → 再渲染验收）；模板测试：换竞品名若仍贴合，说明还没做出选择。

**何时用。** 落地页/仪表盘/移动端屏看起来「很 AI」时做审计或去 slop，尤其动效章可与 Emil 的 remove-animations 联用。

**可带走的一点。** 悬停用颜色/表面变化，按压缩小尺度；列表不要永远按 index stagger——最多给主内容一次短入场。

### [Android M3E × Nav3 · MotionScheme 与共享轴转场](https://github.com/boxiaolanya2008/android-m3e-nav3-skill)

**类型：** skill / 规范

**是什么。** 2026-11-04 的 Android 智能体技能包：强迫走 **Navigation 3 + Material 3 Expressive**，避免升依赖后仍写旧组件。动效相关硬规则写在 [`SKILL.md`](https://github.com/boxiaolanya2008/android-m3e-nav3-skill/blob/main/material3-expressive-navigation3/SKILL.md) 与 [`references/m3e.md`](https://github.com/boxiaolanya2008/android-m3e-nav3-skill/blob/main/material3-expressive-navigation3/references/m3e.md)：主题唯一入口 `MaterialExpressiveTheme` + `MotionScheme.expressive()`，页面里手写 `spring(...)` / `tween(...)` 算违规；空间位移用 spatial spring，颜色/透明度用 effects，同屏最多一个「大位移」。[`references/nav3.md`](https://github.com/boxiaolanya2008/android-m3e-nav3-skill/blob/main/material3-expressive-navigation3/references/nav3.md) 把转场拆成 `transitionSpec` / `popTransitionSpec` / `predictivePopTransitionSpec`：前进共享轴位移+轻缩放、返回必须镜像方向、手势返回可中断；全局只留一层 Scaffold 在 `NavDisplay` 外，否则顶栏整块重绘会打断连续感。

**何时用。** 新建或迁移 Compose 应用到 Nav3 + M3E，且要 Agent 别偷偷退回 `navigation-compose` 与时长缓动。

**可带走的一点。** 先搜仓库有没有 `MotionScheme` + `Emphasized` + `MaterialExpressiveTheme`——三者皆无就是普通 M3，不是 Expressive。
