# 2026-10-23 动效日报

昨天报过 Motion 14.5 的 scopeMotion；同日稍后的 14.6.0 补上 Reorder 键盘抓取重排，以及测试用的 `processFrame` / `stepFrames`。另两则：一套克制派 React motion 配方 + Agent Skills（Terra），以及一篇把 Emil apple-design 17 节公式跑进真实 bottom sheet 的中文实测长文。

### [Motion 14.6.0 · Reorder 键盘重排 + processFrame](https://motion.dev/changelog)

**类型：** 库

**是什么。** 2026-10-20 发布的 Motion minor（changelog：https://motion.dev/changelog ）。相对已报过的 14.5：`Reorder` 增加 Grab-and-move 键盘重排——键盘用户也能抓起一项并移动完成排序，补上长期缺失的无障碍缺口（此前拖拽重排基本只能鼠标/触控）。同版新增 `processFrame`（在时刻 `t` 手动推进 frameloop）与 `stepFrames`（测试里同步按 `duration` 推进帧时间），并把 `MotionGlobalConfig.useManualTiming` 相关行为收紧，方便确定性单测。修复包括：tree-shaking 改善；`layoutId` 部分场景跳动；Reorder 自动滚动速度与刷新率解耦；在 `onDrag` 内关掉 `drag` 时的动画；共享布局动画对自身 `scale`/`x`/`y` 双重应用；接管 `layoutId` 时误重放挂载动画；SVG 样式更新与 `useTransform` 取值解析。文档仍见 https://motion.dev/docs/react-reorder 。

**何时用。** 待办/标签/看板等已用 `Reorder.Group` + `Reorder.Item` 的列表，需要键盘可达；或写动效单测时要可控推进时间轴。

**可带走的一点。** 升级到 14.6 后，Reorder 列表别再只验收拖拽：用 Tab 聚焦项、验证能抓取并箭头/方向键移动排序。单测里用 `stepFrames` 推进时长，少依赖真实 rAF 抖动。

### [Terra Motion Skills · 克制配方 + 三支 Skills](https://github.com/joaquimftt-web/terra-motion-skills)

**类型：** 组件 / skill

**是什么。** 2026-10-20 起公开的独立 React motion 配方仓（MIT，与 Motion 官方无隶属）：本地包 `@motion-skills-lab/motion-recipes` + tokens，外加三支可给 Agent 读的 Skills（`motion-foundations`、`microinteraction-design`、`scroll-motion`）。Showcase：https://joaquimftt-web.github.io/terra-motion-skills/ 。公开基线侧重 Button Feedback（约 140ms、CSS、无 scale）与 Accordion Transition（约 180ms、Motion 控高度）；PR 候选还带 Presence / Async State / Navigation Indicator / Scroll Reveal / Staggered Entrance / Scroll Progress 等，时长多落在 160–260ms，stagger 约 50ms。强调：React 状态是真相源，动画结束不授权业务动作；`prefers-reduced-motion` 系统优先；关闭面板用 `aria-hidden` + `inert`；导入走显式 subpath，不绑死 showcase。锁文件钉在 React 19.3 + Motion 14.3。

**何时用。** 要一套「默认短、可中断、可降动」的产品微交互起点，或给 agent 一份带数字的 foundations skill，而不是再抄一套弹簧玩具。

**可带走的一点。** Button 先 110–160ms 只做色/边/焦点；Accordion 默认 180ms 且快速连点必须能反转——别等动画结束才放行点击。需要降动时跟系统走，不要用 `reduceMotion={false}` 强行盖过 OS。

### [apple-design skill 实测：17 节公式进 bottom sheet](https://yanchen.app/blog/apple-design-skill-claude-code/)

**类型：** 设计哲学 / skill 用法

**是什么。** 2026-10-20 发布的繁中长文（读后译为此简报）：作者实测 Emil Kowalski `emilkowalski/skills` 里的 `apple-design`（把 WWDC《Designing Fluid Interfaces》等改写成网页向 17 节）。同一需求写「下拖关闭 bottom sheet」：不点名 skill → 多为固定时长 CSS transition + 距离门槛；点名 `/apple-design` → 自写 spring、近 100ms 速度采样交接、动量投射 `(v/1000)*d/(1-d)`（d≈0.998）、橡皮筋 `c=0.55`、动画中途可抓住、以及 `prefers-reduced-motion`。文中用 Playwright 校验上拉超顶位移与公式一致。另记踩坑：装了 skill 不等于会触发——未点名连跑 3 次只触发 1 次。作者随后把博客真站改了一轮（按下即时反馈、可中断筛选淡入淡出、reduced-motion 只砍位移保留色/透明度等）。

**何时用。** 要给 agent 写拖拽/抽屉/sheet 时强制带上原生手感公式，或验收「装了 Emil skill 有没有真的用上」。

**可带走的一点。** 手势类需求直接写 `/apple-design`（或「依照 apple-design skill」）；验收看代码里有没有 spring、速度交接、0.998 / 0.55，比只看安装日志准。
