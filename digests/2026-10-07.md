# 动效简报 · 2026-10-07

今天六件事。最值得收藏的是 `m3-expressive-foundations`：它把 Material 3 Expressive 的弹簧体系完整搬到网页，给出每档弹簧的阻尼比、刚度、到位时间和过冲率，还解释了为什么颜色和透明度永远不能回弹。`frontend-craft` 是一套写得很克制的前端 skill，动效部分有一张浮层分层时间表和一套 token。`Motionbook` 是中文作者的高质量 UI 动效复刻库，每个例子都附来源、权利说明和验证记录。`animation-library` 是 12 个经过三引擎实测的 Next.js + GSAP 动效 skill。`motion-design-skills` 是一个从「找机会」到「审查交付」的六步动效工作流，明确把「不加动画」当成合法结论。最后是 Emil Kowalski 的短文《Friction as a Feature》，讲 AI 让做东西太便宜之后，作品为什么会显得空洞。盯着的 Emil skills、LottieFiles skill、gsap-skills、vercel-labs、AlphaXe 本窗口没有新提交；mblode 只给 ui-design 加了压力测试模式（与动效无关），Motion 仓库有合并但没有新版本。

### [m3-expressive-foundations（Material 3 Expressive 网页基础 Skill）](https://github.com/shimonsalamon/m3-expressive-foundations)

**类型：** skill / 规范

**是什么。** `shimonsalamon/m3-expressive-foundations` 是一个非官方的 Claude Code skill，把 Material 3 Expressive 的基础规则（颜色、字体、形状、动效、高度、交互状态、布局）落到任意前端框架，并附一份可直接引入的 CSS token 文件。动效参考 `references/motion.md` 有一千多行，核心是弹簧模型：两种方案（Expressive 会过冲后回弹，Standard 平滑到位），三档速度（fast / default / slow），两类弹簧（spatial 管位置、尺寸、圆角，effects 管颜色、透明度）。作者自己算了每档弹簧从静止出发到达 95% 的时间、完全稳定的时间和过冲率，例如 Expressive 的 fast spatial 是 90ms 到 95%、360ms 稳定、过冲 9.48%。网页实现给了两套辅助变量：一套是 Google 官方的「弹簧转 cubic-bezier」对照表，一套是作者用 `linear()` 精确描出的弹簧曲线（误差不超过 0.002，需 `@supports` 兜底）。拖拽、甩动、快速连点这种需要继承速度的场景，文档明确说两套 CSS 都不够，要在 JS 里跑真弹簧，并给了实现。它不是组件规范，只管「所有组件共用的底层规则」。

**何时用。** 要在网页上做 Material 风格的产品，或者想给自己的设计系统定一套「按尺寸选弹簧」的规则，而不是每个组件各写各的时长。

**可带走的一点。** **颜色、透明度、阴影一律用阻尼比 ζ = 1 的不过冲弹簧。** 透明度被夹在 0–1 之间，过冲会变成提前「撞墙」停下；颜色过冲会冲到两个状态都不属于的色相，看起来像闪了一下。另外，**弹簧档位按元素大小和移动距离选，不按重要程度选**：小控件再重要也用 fast，慢弹簧只会让它显得迟钝；想突出一个瞬间，就给它更大的位移、形状变形，或局部切到 Expressive 方案（`data-motion-scheme="expressive"`），全产品这种时刻控制在一两个。

### [frontend-craft（有意识的网页 UI Skill）](https://github.com/enzodevs/frontend-craft)

**类型：** skill

**是什么。** `enzodevs/frontend-craft`（MIT）是一个面向编码 agent 的前端 skill，覆盖产品推理、视觉系统、完整状态、无障碍和动效，安装方式是 `npx skills add enzodevs/frontend-craft --skill frontend-craft`，不需要 API key 或后端。动效部分 `references/motion.md` 要求动手前先写一份「动效论点」：哪个是唯一值得精心设计的焦点时刻、哪些状态变化需要解释前后关系、哪些控件需要反馈、性能预算是多少。它明确说「通用的淡入上浮、悬停抬起、视差、滚动揭示」都不算论点，每个区块用同一种进场是典型的 AI 默认做法。运行时选择按从轻到重：沿用项目现有方案 → CSS → WAAPI → View Transitions / FLIP → Motion 或 GSAP，二者已能解决就不要再加第二个。附 23 个动效配方和一套时长 / 缓动 / 位移 / 缩放 / 模糊 token，原始配方和 token 来自 Jakub Antalik 的 transitions.dev，作者在 provenance 里标清了哪些是自己的改动。

**何时用。** 让 agent 写产品界面时，想要它先想清楚「这里为什么要动」，而不是到处撒进场动画。

**可带走的一点。** 浮层（菜单、对话框）照这张时间表起步，核心原则是**重叠，不要排队**：触发按钮反馈从 0ms 开始，持续 60–100ms；遮罩从 0ms 开始，140–200ms；面板在 0–20ms 内开始，180–280ms，配 4–12px 位移或 0.97→1 缩放；内容组 20–50ms 开始，组间隔 20–35ms，累计偏移不超过 100ms；退出 120–180ms，遮罩和面板一起走，不做错开。另外两条硬规则：**永远不写 `transition: all`**；可交互的开合用 transition（能从当前状态反向），不用 keyframes（中途关闭会跳或重播）。

### [Motionbook（UI 动效与微交互复刻集）](https://github.com/blueberrycongee/motionbook)

**类型：** 组件 / skill

**是什么。** `blueberrycongee/motionbook` 是一个中文作者维护的 UI 动效复刻库，目前有四十多个例子，每个都有 GIF 预览：ChatGPT 的画中画吸附、Apple Music 歌词、macOS 神灯效果、弹簧验证码输入框、可拖拽任务卡片堆、灵动岛连胜提示等。和一般的「动效合集」不同，每个例子目录里都有来源说明（`PROVENANCE.md` / `SOURCE.md`）、权利说明和验证记录（`VALIDATION.md`），会写清楚哪些是测量过的参考行为、哪些是作者补充的演示部分、哪些在当前环境下没验证过。比如画中画例子注明：预览是离线渲染的，不是真实录屏；求解器 60Hz、采样 30fps；原生 macOS 运行效果未验证。仓库还带一个 agent skill（`skills/motionbook/SKILL.md`），教 agent 怎么挑例子、只读需要的文件，再改写到目标项目的技术栈里。注意：仓库根目录没有统一许可证，各例子的许可要分别看。

**何时用。** 想做某个有名的产品级微交互（吸附、甩动、形变、进度挤压），需要一个已拆好状态、几何和弹簧参数的参考实现时。

**可带走的一点。** 它的 skill 里有一条值得所有动效 agent 照抄的交付规则：**GIF 或 MP4 能播放，只证明导出的序列没问题，不证明应用里的输入处理、浏览器布局或原生运行时能用。** 汇报时要分开说三件事：实际跑过什么、离线渲染了什么、还有什么没测。

### [animation-library（12 个实测过的动效 Skill）](https://github.com/lscottart/animation-library)

**类型：** skill / 组件

**是什么。** `lscottart/animation-library`（MIT）是一位给建筑事务所做网站的设计师兼开发者整理的 12 个 Claude Code 动效命令，每个只做一个小动效，写进 Next.js 项目：标题按行遮罩升起、列表悬停色块逐行滑动、字母 15ms 波浪滚动、单向擦除按钮、跟随阅读的章节小地图、光标标签、数字滚动（从最右位开始，符号不动）、兄弟元素变暗等。底层用 GSAP 3.15，全部尊重 `prefers-reduced-motion`。它最有价值的是测试方式：每个 skill 原样应用到三个没准备过的新项目（App Router + Tailwind v4 / v3、Pages Router 无 Tailwind），在 Chromium、Firefox、WebKit 的开发和生产构建下逐帧测量（例如色块滑到一半在哪、哪一位数字先滚）。然后故意破坏每个机制，确认检查会失败，失败结果写进每个 skill 的「要避免的失败模式」。安装是把 `skills/*.md` 复制到 `~/.claude/commands/animations/`，用法如 `/animations:number-roll the local time in the footer`。

**何时用。** 做作品集或事务所类网站，需要几个有质感但不花哨的细节动效，并且希望 agent 写完能自己验收。

**可带走的一点。** 来自「移动高亮块」这个 skill 的三条失败模式：**原本没有高亮时，第一次悬停要直接出现在目标项上，不要从上一个位置滑进来**；当前页的高亮要用 CSS 在首屏就画好，不要等 JS（慢网络下访客先看到的是空白）；**等 `document.fonts.ready` 后重新测量尺寸**，否则高亮块会按回退字体的宽度算。

### [motion-design-skills（产品动效六步工作流）](https://github.com/danisalo/motion-design-skills)

**类型：** skill

**是什么。** `danisalo/motion-design-skills` 是一个面向 SaaS、网页、PWA 和原生界面的动效 skill，只有一个入口 `motion-design`，由它按需调用六个内部工作流：发现（最多给五个值得加动效的地方，同时列出静态替代方案和被否决的候选）、审计、设计（状态、触发、时长、中断和无障碍等价方案）、编排（按「准备 → 变化 → 结果」写节拍表和总时长预算）、实现、审查。README 第一段就写明「保持静止也是合法的结论」。如果你只说「优化一下动画」而没明确要求改代码，它只出审计报告和计划，不动源码。每个任务都会加载原则和无障碍两份参考，运行时或设备上没能检查的项目会标为「未验证」。

**何时用。** 想让 agent 先判断「这里该不该动」，再按规格实现，最后对照规格审查自己的改动。

**可带走的一点。** 它的时长参考把一次动效拆成**四个时钟**来记录：开始延迟、到达有意义位置、完全稳定、下一次输入可用。视觉上还在稳定时，元素可能已经可以操作了。错开动画的总时长公式是 `(N − 1) × 间隔 + 单项时长`，例如 12 项、每项错开 50ms、单项 200ms，要到 750ms 才结束；工具型内容的整组预算通常控制在 400–500ms 以内，否则就去掉错开。起步时长：按压反馈 100ms、小浮层 160ms、下拉 180ms、弹窗 / 抽屉 240ms。

### [Friction as a Feature（Emil Kowalski）](https://emilkowal.ski/ui/friction-as-a-feature)

**类型：** 设计哲学

**是什么。** 这是 Emil Kowalski 网站首页最新的一篇短文。他的论点是：我们一直把「摩擦」当坏东西，但它其实还在做另一件事：逼我们在动手之前先想清楚。AI 出现之前写代码很贵，这个成本自然筛掉了很多不值得做的想法；现在一个想法几分钟就能变成应用，门槛一下子没了。他承认便宜的构建本身也是一种思考，做 A 和 B 两个版本来比较，往往比空想更能验证想法，但前提是你真的去验证。没有摩擦时，没有什么能阻止你把 A 和 B 都发出去。他认为这就是大家反感最近一批 vibe-coded 应用和 UI 库的原因：背后很少有思考，它们「不像是被设计出来的，只是存在着」。

**何时用。** 团队在讨论「AI 生成的界面为什么显得廉价」，或者你在决定一个组件 / 动效值不值得做的时候。

**可带走的一点。** **工具不再替你做筛选，筛选就得变成刻意的步骤。** 落到动效上，就是每加一个动画之前先回答它在解释什么，答不上来就不加，这和今天前面几个 skill 要求先写「动效论点」是同一件事。
