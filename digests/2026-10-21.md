# 2026-10-21 动效日报

昨天 Claude Skills 目录上线了一对互补的产品动效 skill：一个管「要不要动、怎么定时长/缓动」，一个管「用平台还是库、怎么验 60fps」。同日 Atlassian Design Technology 团队发文，把「在真代码原型里测 motion」写成了组织级工作方式。

### [ui-motion（Claude Skills）](https://claudeskills.page/skills/design/ui-motion/)

**类型：** skill / 设计哲学

**是什么。** 2026-10-20 首发（MIT）的界面动效口味 skill：给每个动画派一份工作（反馈 / 定向 / 连续感 / 注意力），再按尺寸套时长表——按压反馈 100–150ms、tooltip/开关 150–200ms、下拉/toast 200–250ms、模态/抽屉 250–350ms、路由/共享元素 300–450ms；列表 stagger 每项 20–50ms、总 stagger 封顶约 300ms。进入用减速（如 `cubic-bezier(0.16, 1, 0.3, 1)`），退出用加速且约为进入的 70–80%，同屏位移用标准 ease-in-out，拖拽松手才用弹簧。只动 `transform`/`opacity`；状态切换要可中断（CSS transition 或可重定向的弹簧，不要写死关键帧）。明确反对：全站 fade-up 40px、卡片一律 `hover:scale(1.05)`、处处弹跳弹簧、`transition: all 0.3s ease`、600–1000ms「高级感」。安装：`curl -fsSL https://claudeskills.page/install.sh | sh -s -- ui-motion`。

**何时用。** 给 agent 定产品微交互的数字预算与反廉价清单；或审查「慢、飘、弹、卡」的现有动效。

**可带走的一点。** 退出要比进入快约 20–30%，并且**同形状反方向**——模态开用 scale+fade，关也用同一套，只是更快；换形状会像坏了。把 `--ease-enter` / `--ease-exit` / `--duration-fast|base|slow` 做成 token，不要每处手写 `0.3s ease`。

### [web-animations（Claude Skills）](https://claudeskills.page/skills/frontend/web-animations/)

**类型：** skill

**是什么。** 同日配套的实现向 skill：先选最轻工具——单元素状态用 CSS `transition`；循环装饰用 `@keyframes`；从 `display:none` 进场用 `@starting-style` + `transition-behavior: allow-discrete`；路由/列表重排用 View Transitions；滚动量用 CSS `animation-timeline`；命令式用 WAAPI `element.animate`；React 布局/退场/手势才上 Motion（`motion/react`）；复杂时间轴/滚动叙事才上 GSAP。性能红线：别动 `width`/`height`/`top`/`box-shadow`；禁止 `transition: all`；`will-change` 用完即撤。折高用 `grid-template-rows: 0fr→1fr`。验收：DevTools Performance 开 4× CPU 节流，动效区间无长帧、无每帧 Layout/Paint；Rendering 里模拟 `prefers-reduced-motion` 后只留淡入或瞬间态。安装：`curl -fsSL https://claudeskills.page/install.sh | sh -s -- web-animations`。文内写明：口味与数字预算归 `ui-motion`，本 skill 管选型与落地。

**何时用。** 已经知道「该不该动、多长」，需要 agent 选 CSS / VT / Motion / GSAP 并写出可中断、可降级的实现时。

**可带走的一点。** 平台优先：dialog/popover 进退场先试 `@starting-style`，别默认装库。`opacity:0` 结束时还要点击 —— 收尾要加 `visibility:hidden` 或 `inert`。总 stagger 别拖过约 300ms。

### [Atlassian · The Craft of Design Technology](https://x.com/faridsabitov/status/2112699970063315322)

**类型：** 设计哲学

**是什么。** 2026-10-21 发布的 Atlassian Design Technology 实践长文（X Article）。团队把自己的工作拆成抬地板与抬天花板：地板是 ADS MCP/CLI、DESIGN.md 级结构化设计语境、平台包可发现性与质量闸，让 agent 默认吐出系统对齐的界面而不是通用 indigo 模板；天花板是代码即活规格——在真实技术栈的沙箱（Protobox）里做高保真原型，在进生产工程之前就测边缘态、动态数据、响应式，以及 **motion**。文中举例 Teamwork Graph 站用编码原型解渐进披露、磁性节点遍历、错开计数与物理调参交互；并提到把生成式 UI 收成可评估的组件词表与预检闸。不是动效教程，是把「动效属于可运行规格」写进组织流程的案例。

**何时用。** 想推动团队用代码原型验收动效，或给 agent 接设计系统 MCP/语境层，而不是只在静态画布上标时长时。

**可带走的一点。** 动效验收点前移：在**真实栈原型**里试打断、响应式和边缘态，再交给生产工程——别等实现阶段才第一次看到 spring 手感。给 agent 的设计语境要和组件/token 同级可机读。
