# 2026-10-29 动效日报

今天的主菜是 Emil 新开的 `remove-animations`：只删不增，把「看起来不错」赶出法庭。另有 Motion 14.7 的 `transition.out` 与可改写时间轴，以及两套把克制动效写进 CI 的 agent skill（deburr、visant-motion）。

### [remove-animations · Emil 只删不增的减法 skill](https://github.com/emilkowalski/skills/tree/main/skills/remove-animations)

**类型：** skill / 设计哲学

**是什么。** 2026-10-28 合入 `emilkowalski/skills` 的新 skill（commit `a81dbca`），与 `find-animation-opportunities` 成对：后者找该加的，这个只负责砍。硬规则——**只能减法**，不许加动画、不许「顺便调参当优化」。决策树：键盘高频路径 → 删；每天百次以上 → 删；图表/表格等功能数据 → 删（除非在表现数值变化）；说不出名字的目的 → 删（除非极偶尔的 delight）；每天几十次 → 减量。附带一张 **Reduce 表**：hover 缩放改颜色/透明度 ≤150ms `ease`；滑入/缩放改 opacity 150ms ease-out；>300ms 压到 200–250ms；stagger 单项 >80ms 或总计 >300ms → 单项封顶 30ms 或整组淡入；无限循环 → 播一次或改静态。猎杀清单：命令面板、Tab、路由过渡、`whileInView`、`transition: all`、闪不到 300ms 的骨架。还列了删除时的坑：`initial` 把 opacity 藏成 0、`onExitComplete` 空等、layout 动画遮住跳变、动效结束后才给焦点。输出必须是：Removed/reduced 表 + Kept（2–5 条并写目的）+ Cleanup。文内指向 https://emilkowal.ski/ui/you-dont-need-animations 。安装仍用：`npx skills add emilkowalski/skills`。

**何时用。** Agent 或同事默认「先加一点动画」；上线前要做减法审查；或产品已经堆满无目的的 hover/入场。

**可带走的一点。** 把每段动画拉上法庭——「好看」不是辩护理由；说不出目的就删，高频路径优先删。

### [Motion 14.7.0 / 14.7.1 · transition.out 与可改写时间轴](https://github.com/motiondivision/motion/releases/tag/v14.7.0)

**类型：** 库

**是什么。** 2026-10-27 发布的 Motion **14.7.0**（随后 **14.7.1** 补丁）。以 GitHub [CHANGELOG](https://github.com/motiondivision/motion/blob/main/CHANGELOG.md) 为准（站点 changelog 当时仍停在 14.6）。新增：`animate` 可变时间轴序列（mutable timeline sequences）与相对 label 偏移；`useScroll` 增加 `scrollXLength` / `scrollYLength`；`Reorder` 可与 LazyMotion 兼容导入；`motion` 支持 **`transition.out`**，专门描述从当前态退出时的过渡。修复挑几条：过阻尼弹簧贴底、拖曳轻甩后惯性、`layoutId` 相对最近 `layoutRoot`、挂载后可改 `layoutId`、横向 `useScroll`、`useSpring` 体积约 −30%、`background-color` 回到主线程。14.7.1：布局动画打断时把 transform 降回 CPU，避免错层。官网 changelog 入口：https://motion.dev/changelog 。

**何时用。** 已在用 Motion/Framer Motion 的产品 UI；需要退出动画与进入动画分开写，或要在运行中改写时间轴序列。

**可带走的一点。** 退出别再硬塞进同一条 `transition`：用 `transition.out`；需要可编辑的编排就上 mutable timeline，别手搓一串 `await animate`。

### [deburr · 去「AI 毛边」的 UI 打磨 skill](https://github.com/ilkcankose/deburr)

**类型：** skill

**是什么。** 2026-10-27 开源的 Claude/agent skill（`npx skills add ilkcankose/deburr`）。三根柱子：没有东西突然变；没有地方挤；层级一眼清楚。动效写在 SKILL.md 与 `rules.md`：状态变化要缓；**打字、键盘、重复操作绝不加 delay**；焦点环瞬时；新视图短淡入 + 小位移；**150–300ms ease-out**，退出更快；缩放约 0.95–1；尺寸变化用 morph；加载 <~300ms 不露 loader；bounce 极少用；只动 `transform`/`opacity`；禁止 `transition: all`；尊重 `prefers-reduced-motion`。附 `scan.mjs` 扫描：`transition: all`、从 0 起缩放、拖沓时长、默认蓝等。另有 `native.md`（SwiftUI / RN）。缓动默认常引用 `(.22,1,.36,1)`。

**何时用。** Agent 刚吐出一版「能用但毛刺多」的界面，要一轮可执行的打磨；或想在 PR 前自动扫廉价动效信号。

**可带走的一点。** 动效的工作是**跟上变化**，不是给每个状态贴装饰；键盘路径零延迟。

### [visant-motion · 单源 token + lint/codemod 的 Emil 落地包](https://github.com/pedrojaques99/visant-skills-public/blob/main/visant-motion/SKILL.md)

**类型：** skill / 工具

**是什么。** 2026-10-28 公开的 `pedrojaques99/visant-skills-public` 里的 `visant-motion`（安装：`npx skills add pedrojaques99/visant-skills-public --skill visant-motion`）。明确蒸馏自 Emil skills 与 Apple 流体界面。总规则：**SSoT——组件里绝不硬编码 cubic-bezier / duration**。Token 示例：`--ease-out: cubic-bezier(0.23,1,0.32,1)`、ease-in-out `(0.77,0,0.175,1)`、抽屉 `(0.32,0.72,0,1)`；`DUR.press` 0.12 / fast 0.16 / base 0.2 …；UI 动效压在 300ms 内。时长表：按压 100–160ms、tooltip 125–200、下拉 150–250、模态 200–300。等待阈值：100ms 当瞬时 / 300ms 才出 loader / 至少显示 500ms。提供 `useDelayedFlag(isPending, { delay: 300, minVisible: 500 })`。工具：`motion-lint.mjs`（12 条：UI 上用 ease-in、scale-zero、`transition: all`、过慢 UI 时长、硬编码曲线/时长、动 layout 属性等）、`codemod-duration.mjs`、`--fix`。起步文件见 `assets/motion-ssot-starter/motion.ts`。同仓还有反 slop 审计 sibling `visant-killer`。

**何时用。** 要把 Emil 式克制写进设计系统与 CI；讨厌每个组件各写一套魔法数字。

**可带走的一点。** 先维护一份 CSS/JS 镜像的 token 文件，再让 lint 拦硬编码——比事后口头说「别乱写时长」管用。
