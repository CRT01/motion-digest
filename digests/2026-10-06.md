# 动效简报 · 2026-10-06

今天四件事，主线都是「弹簧该用在哪、不该用在哪」：`apple-design` 把 WWDC《Designing Fluid Interfaces》落到网页，讲清楚拖拽释放时怎么把速度交给弹簧，以及阻尼比和阻尼系数不能混用；`anti-slop-web` 的动效参考用一个 MOTION 档位（1–10）决定产品该动多少，并把「每个过渡 500ms 加回弹」列为典型 AI 误用；`bencho-frontend` 把 bencho.dev 的 48 个微交互整理成中文 skill，给出按压 / 状态 / 展开三档时长起点；`glass-navbar` 是一个零依赖的悬浮胶囊顶栏，用来演示为什么尺寸变化要用弹簧积分，而不是 CSS transition。盯着的 Emil skills、LottieFiles skill、gsap-skills、vercel-labs、AlphaXe 本窗口没有新提交；Motion 仓库有修复（动画晚于 40ms 才开始时从第一帧起播），但还没发版，暂不收录。

### [apple-design（中文 Apple 设计 Skill）](https://github.com/MrRoam/apple-design-skill)

**类型：** skill

**是什么。** `MrRoam/apple-design-skill` 是一个中文 skill，把 Apple 的设计原则转成网页上可执行的指引，重点覆盖手势、可中断弹簧、排版和 Liquid Glass。作者写明这不是 Apple 官方发布的内容，并在文中区分了三类东西：官方原则、WWDC 课程里的案例，以及作者自己的网页实现建议。参考资料按任务加载，涉及拖拽、抽屉、惯性和中断时只读 `references/interaction-motion.md`。这份文档的核心规则是：拖拽过程中直接更新位置，不要用缓动去追指针；松手时用**当前显示位置加当前速度**启动弹簧；再次抓取时从画面上的位置接管，而不是从上次的目标重新开始。文中给出了惯性落点投影函数（`decay = 0.998`/ms）和边界橡皮筋函数（`constant = 0.55`），但都标注为可调的模型起点，不是浏览器原生参数。还附带一个无需构建的 Liquid Glass 演示页，作者也说明它只用了背景模糊加近似高光，并不等同于系统级渲染。

**何时用。** 做抽屉、底部面板、可拖拽卡片、滑块，或者想要「苹果式跟手感」又不想把整套 HIG 搬进网页的时候。

**可带走的一点。** **Apple 的阻尼比 `ζ = 1.0` 不能直接写成 Motion 的 `damping: 1`。** 两者的换算是 `c = 2 · ζ · √(k · m)`，所以 `mass: 1, stiffness: 225, damping: 30` 才是一组临界阻尼的网页起点。需要承接手势速度时，用物理型弹簧并传入 `velocity`（单位 px/s）；`duration + bounce` 这种时间型弹簧不会继承手势速度。

### [anti-slop-web · motion 参考](https://github.com/YoussefMadkour/anti-slop-web/blob/main/skills/anti-slop-web/references/motion.md)

**类型：** skill / 设计哲学

**是什么。** `YoussefMadkour/anti-slop-web`（10 月 5 日）是一套面向 Claude Code 的网页设计推理插件，包含五个 skill（web、a11y、responsive、code、copy）。它的立场和常见的禁用清单相反：**一种技法不会因为 AI 常用就变坏，只有在没有产品、内容、品牌、层级或可用性理由时出现才算坏**；也不要为了躲开「AI 味」把界面做得怪异。动效这一章先规定每个动画必须承担五种职责之一：反馈、状态变化、空间连续、吸引注意（只一次）、叙事，否则删掉。然后在项目的 `DESIGN.md` 里设一个 MOTION 档位：1–3 档只有悬停、聚焦、按压反馈，没有滚动效果，适合运营后台、数据工具、仪表盘；4–6 档允许解释变化的过渡和轻量揭示，适合营销站和电商；7–10 档才允许编排序列、滚动叙事、物理效果和 WebGL。实现层也分了五级，从 CSS 到 WebGL，要求用能达到效果的最轻一级，并且同一个元素上不要跑两套系统。

**何时用。** 让 Agent 做落地页或后台之前先定「这个产品该动多少」；或者评审 AI 生成的前端时，需要一个不靠个人口味的判断标准。

**可带走的一点。** **默认内容可见，动效是后加的。** 只有在脚本运行后给 `<html>` 加上 `.js` 类，并且满足 `prefers-reduced-motion: no-preference` 时，才把 `.reveal` 设成初始隐藏；这样脚本失败时不会有内容一直看不见。时长起点是：按压约 100ms，悬停 100–150ms，菜单和手风琴 200–250ms，对话框和抽屉 200–350ms，退场通常比进场短。界面反馈超过约 400ms 就会显得拖沓。

### [bencho-frontend（Bencho 微交互 Skill）](https://github.com/GuangGOvO/bencho-frontend-skill)

**类型：** skill

**是什么。** `GuangGOvO/bencho-frontend-skill`（10 月 5 日，v0.1.1）是一个中文 skill，把 [bencho.dev](https://bencho.dev/) 上能观察到的 48 个组件、7 类微交互整理成设计、实现和评审指导。它不是官方 skill，也不打包原站的商标、字体和图片。核心内容有三部分：`patterns.md` 按用户任务选模式，例如高影响操作用内联确认或滑动确认，并且必须有键盘替代；`motion-and-accessibility.md` 规定动效、输入和可访问性规则；`assets/recipes/` 下有三个不依赖动效库的原创 React 示例：异步内联确认、原生图片对比、浮动标签。仓库还带一个每天检测上游变化、发现新指纹就开 Issue 的 GitHub Action。

**何时用。** 给提交、开关、选择、确认这类控件加微交互，同时需要守住键盘、触屏和减少动效的时候。

**可带走的一点。** 时长起点是：**按压反馈 80–140ms，状态转换 160–240ms，较大的展开 240–360ms，轻按缩放 0.97–0.99**。拖动期间不套用这些过渡，每帧直接跟随输入，松手后另外处理落定。弹簧用于释放、吸附和形态恢复，进场和退场用固定时长。不要同时把手势目标和弹簧目标当成当前位置，也不要写 `transition: all`。

### [glass-navbar（悬浮玻璃胶囊顶栏）](https://github.com/ningqi24/deepseek-style-floating-navbar)

**类型：** 组件

**是什么。** `ningqi24/deepseek-style-floating-navbar`（10 月 3 日）是一个零依赖、无需构建的顶栏组件，只有两个文件，gzip 后 5.5KB。页面滚过阈值后，顶栏左右各内缩 80px，高度从 58px 降到 48px，并淡入磨砂玻璃背景。作者说明这是参照 DeepSeek 官网效果的独立实现，与 DeepSeek 没有关联。它的看点是 README 里讲透的一个取舍：`width`、`padding`、`height` 如果用 CSS transition，滚到一半往回滚时会「硬生生掉头」，因为 transition 只关心起点到终点的进度，不关心当前速度。所以组件的尺寸变化用弹簧积分驱动，外观（玻璃淡入）仍然用 0.3s 的 CSS 过渡。默认参数是 `k = 180`、`c = 28`、`m = 1`，略高于临界阻尼 26.8，作者的说法是「来回振荡那种弹簧感其实很廉价」。所有设计数值都是 CSS 变量，演示页有实时调节面板。

**何时用。** 想做「滚动后收成胶囊」的顶栏，或者需要一个小而完整的范例，向团队解释为什么可逆的尺寸动画要用弹簧。

**可带走的一点。** 手写弹簧循环时照抄这四条工程细节：**单步 `dt` 上限夹在 1/30 秒**（切回标签页或严重掉帧时积分不会炸）；位移和速度都收敛后吸附到目标并停掉 `requestAnimationFrame`；窗口缩放时直接落值，不播放动画；scroll 回调里不读 `getComputedStyle`，token 只在初始化和缩放时读一次并缓存。开启减少动态效果时直接落值。
