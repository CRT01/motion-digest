# 动效简报 · 2026-10-02

本窗口四件事：Motion 升到 **13.5.0**（负 `bounce` 过阻尼弹簧 + 滚动 offset 全部回主线程）；`showmotion` 用 259 张可播卡片给动作起名并吐出可贴进 Agent 的提示词；`motion-playbook` 把滚动叙事站的实测性能规则写成可跑 demo；`growcore-ui` 用德文手册 + shadcn 注册表把 GSAP 时长/曲线 token 和组件绑在一起。盯着的 Emil skills、AlphaXe、mblode、animations.dev、优设猎人（除已收录的 Kobra）本窗口没有新的产品级增量。

### [Motion 13.5.0](https://github.com/motiondivision/motion/releases/tag/v13.5.0)

**类型：** 库

**是什么。** Motion 在 10 月 1 日发了 **13.5.0**（npm 同日上架）。最大产品向改动：`spring` 的 `bounce` 现在接受 **负数（0 → −1）**，用来做**过阻尼**弹簧——启动更快、无过冲、收尾更慢，但到达目标的总时长仍与 `bounce: 0`（临界阻尼）相同，改的是曲线形状而不是 timing。`AnimatePresence` 体积约再小 20%，`useSpring` 约小 10%。滚动侧：`scroll` / `useScroll` 的 **所有 `offset` 动画改回主线程**（相对 13.4.7「更多 offset 走 ViewTimeline」是一次回调）。另修：生产构建清掉 warning/error 文案；值在解析完成前不再渲染。changelog：https://motion.dev/changelog?lib=motion#13-5-0 ；`bounce` 文档：https://motion.dev/docs/react-transitions#bounce

**何时用。** 项目已在 `motion/react`，想要「沉稳落位、不要弹一下」的抽屉/面板/大面过渡，或刚升到 13.4.7 依赖 ViewTimeline offset、需要核对滚动曲线时。

**可带走的一点。** **需要过阻尼手感时写 `transition: { type: "spring", duration: …, bounce: -0.3 }`（约 −0.2～−0.5 常用），不要硬调 `damping` 去猜。** 升到 ≥13.5.0 后，务必在真机重测 `useScroll`/`scroll` 的 offset 进度——13.5 把加速路径收回主线程，曲线可能与 13.4.7 的 ViewTimeline 路径不一致。

### [ShowMotion](https://github.com/bohe76/showmotion)

**类型：** 库 / 规范

**是什么。** `bohe76/showmotion`（9 月 30 日开源）解决「认得动效、叫不出名字、没法跟 Agent 说清楚」：259 个动作、15 类（进出场、滚动、文字、悬停、光标、页面过渡、加载、3D 等），每张卡直播可播，给正式名 + 别名，并附一段可粘贴的提示词（把 `[where]` 换成目标即可）。支持 9 语（含简体中文），另有机器可读的 `/motions.json` 与 `/llms.txt`，并尊重 `prefers-reduced-motion`。站点：https://showmotion.bohehub.com 。栈是 Astro 静态站，无客户端框架。

**何时用。** 和 Agent 结对做产品动效时，需要共享同一套动作名与约束提示，而不是只丢一句「做一个酷炫入场」。

**可带走的一点。** **先让人/Agent 选定动作名（含别名），再贴卡上的 prompt，并保留「只播一次 + reduced-motion 时静置」这两句约束。** 搜索支持中日韩，适合中文团队用「回弹进入」「错落入场」这类本地名对上英文 API 叫法。

### [Motion Playbook](https://github.com/swcstudiospace/motion-playbook)

**类型：** 规范 / 设计哲学

**是什么。** `swcstudiospace/motion-playbook`（10 月 1 日）是 Spectrum Web 滚动叙事站的实战手记：设计规则 + 性能手法 + anime.js v4 / three.js 坑 + 可切换好/坏实现的 demo。手机 4× CPU 下最长任务从 3.3s→0.66s，长滚动阻塞 2.1s→0.5s，Lighthouse 移动 LCP 6.8s→1.4s。设计侧固定五类职责（定向/因果/解释/奖赏/氛围）、每屏一个英雄时刻、时长三档 + 退场约 2/3、滚动只 scrub 不劫持。性能侧强调：布局只读一次、多元素共用预计算 track、首屏用 CSS 入场、idle 停引擎、避开移动内容上的 `backdrop-filter` 与逐词 blur。

**何时用。** 做长页滚动产品演示、营销叙事或 three.js 舞台，需要可量化的「别把页面拖死」清单时。

**可带走的一点。** **滚动场景宁可用少量预计算轨道在一个循环里采样，也不要给每个点挂一条 tween（他们的对比：6 条 vs 706 条）。** 内容必须首帧可见；减动时 snap 到终态并关掉 scrub/循环。

### [growcore-ui 动效体系](https://github.com/jjokkln/growcore-ui)

**类型：** 组件 / 规范

**是什么。** `jjokkln/growcore-ui`（10 月 1–2 日）是面向 Next.js + Tailwind 4 的 shadcn 注册表：德文设计手册（含专门的 `handbuch/bewegung.md`）+ 可安装 Bausteine。动效核 `bewegung` 会随每个组件自动带上——`tokens.ts` 里的 `DAUER`（xs/sm/md/lg = 0.15/0.25/0.45/0.8s）与 `KURVE`（`power3.out` / `power2.in` / `power2.inOut` / `expo.out`），以及 CSS 变量 `--dauer-*` / `--kurve-*`。组件覆盖 staggered 入场、掩码文字、计数、height:auto 折叠、drawer、滚动叙事、FLIP 列表、View Transition 换页等。硬规则：只动 `transform`/`opacity`；`gsap.matchMedia()` 处理减动；CSS 先写起始态防闪；时长曲线只许走 token。安装例：`npx shadcn@latest add jjokkln/growcore-ui/auftritt`。

**何时用。** 要在现有 shadcn/Next 项目里统一 GSAP 动效语言，或抄一套「网站一个英雄时刻、App 只做反馈与状态」的分面策略时。

**可带走的一点。** **退场约等于进场的 70%；UI 反馈压在 250ms 内；stagger 每步 60ms、总量封顶约 0.4s；B2B 不用 elastic/bounce，唯一破例是线上小点的 `back.out(2)`。** 换页走 React `<ViewTransition>`，不要用 GSAP 硬做路由过渡。
