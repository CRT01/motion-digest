# 2026-10-20 动效日报

周末到周二：Motion 把拖拽补进原生 JS API；一条按帧对齐 iOS 的 Liquid Glass 小费组件；Bencho 把 41 个微交互块 MIT 开源；再加上一个可重定时、可导出 60fps 的 UI 动效编辑器。

### [Motion 14.4.0 · JS `drag`](https://motion.dev/docs/drag)

**类型：** 库

**是什么。** 2026-10-18 发布的 Motion 14.4.0（npm 已上 `14.4.0`）给**原生 JavaScript**补上了与 React `drag` 同物理模型的 `drag()`：惯性、轴向锁定、弹性边界、方向锁。用法是 `import { drag } from "motion"` 后 `drag(".box")` 或传入 Element；用 `transform` 的 `x`/`y` 移动元素本身，而不是浏览器原生 Drag and Drop（那套是为搬数据做的，还有 ghost image）。自动设置 `touch-action`、`user-select`、`draggable="false"`。选项含 `axis`、`constraints`（像素盒或容器元素）、`elastic`（默认 `0.35`，也可按边分别设）、`momentum`、`snapToOrigin`、`directionLock`、`propagation`（嵌套拖拽）。`onEnd` 里可接 `animate(".box", { x: 0, y: 0 }, { type: "spring" })` 做松手回弹；`drag` 与 `animate` 共用同一套 `x`/`y`，拖拽开始会打断进行中的动画。返回清理函数可卸掉手势并恢复样式。同日还有 14.3.1 补丁（AnimatePresence 退出完成时机、共享布局旋转插值、加速独立变换残留浮点等）。不是新组件库，是 vanilla 手势层补齐。

**何时用。** 非 React 页面要做可拖滑块、底部 sheet、卡片归位；或想在 JS 里复用与 React `drag` 一致的惯性/边界语义。

**可带走的一点。** 方向锁开启时，**设定锁的那一次移动也要算进位移**——否则 WebKit 合并快滑时可能整段没动。底部 sheet 可在 `onEnd` 用 `info.offset.y > 100 || info.velocity.y > 800` 决定关闭。子元素若是 `<img>`，还要单独设 `draggable="false"` 才不会出 ghost。

### [mortspace/liquid-glass-tip](https://github.com/mortspace/liquid-glass-tip)

**类型：** 组件 / 设计哲学

**是什么。** 2026-10-18 开源的 React 19「Add tip」液态玻璃控件：Pay 旁的小费按钮与弹出选择器是**同一块玻璃**，张开时中间拉出玻璃颈再断开；全程用 response/bounce 弹簧（可中断、不跳帧），标签用同位置模糊交叉淡入而不是滑动。作者对照录了 iOS 26 Mail/Messages 玻璃钮与自己的实现（同 60fps），逐帧得到四步：触按只变暗 → 松手乳白+约 25% 鼓起 → 形状变形 → 新内容最后、略大且模糊地锐化进来。调参把「95% 高度」从约 250ms 无过冲改到约 150ms、1.5% 过冲；合拢修了「耳朵」（隐藏窄缝高出按钮 6px）和「二次锐化」标签 bug。性能上复用缓冲、运动中关透镜滤镜、就地更新 SVG mask、便宜阴影、未变则不重绘，最差帧从约 75ms 压到约 29ms。尊重 `prefers-reduced-motion` / 降低透明度 / 增强对比；依赖仅 `web-haptics`。演示：[feralui.dev/library/liquid-tip](https://feralui.dev/library/liquid-tip)。

**何时用。** 结账小费、或任何「按钮长出面板再折回」的液态玻璃微交互，且要可中断弹簧而不是 CSS 曲线硬切。

**可带走的一点。** 不要跳过「松手瞬间乳白鼓起」那一帧——全速看很顺，慢放才发现缺它会「瘪」。打开时先沿按钮自身列上升、约 60ms 后再变宽，避免横切 Pay。合拢时在玻璃仍乳白时就写入新标签，只锐化一次。

### [cabralorenzo/bencho](https://github.com/cabralorenzo/bencho)

**类型：** 组件

**是什么。** 2026-10-18 把 [bencho.dev](https://bencho.dev) 上的交互块开源到 GitHub：MIT，**41 个 React 块 + 24 个 Web Audio 界面音**（无外部音频文件）。每块是独立文件夹（组件 + CSS + 写清 props 的 README）；复制后装 `framer-motion` 与 `lucide-react`，并引入一次 `tokens.css`（支持 `data-theme="dark"`）。分类覆盖 Slide（如 wake-slider：无拇指的细条量程，快拖时身后条弹簧弹起）、Hover（toast-stack 悬停弹开、image-accordion 挤让）、Drag（slide-confirm、pull-to-refresh、image-compare 甩动贴边）、Press（Like 心跳爆发、liq-toggle 液滴拉伸、dynamic-island 形态一体展开）、Type/Select/Swipe 等。站上每个块有 Copy prompt 方便 agent 接入。仓库是精选子集；Pro 另有 120+ 块（本条只谈 MIT 开源部分）。此前日报只覆盖过中文整理 skill，这次才是可复制源码仓。

**何时用。** 要可粘贴的产品微交互起点（点赞、确认滑动、液态开关、岛状活动条），并顺手接上轻量界面音。

**可带走的一点。** 先拷一块再改 props，而不是从零捏时长——站点上拧过的旋钮与源码 props 一一对应。音效用 `play("tick")` 这类命名，不要另挂 mp3。

### [vanechkq/ui-motion-editor](https://github.com/vanechkq/ui-motion-editor)

**类型：** 库 / 工具

**是什么。** 2026-10-19 的本地 UI 动效编辑器：HTML/CSS/SVG 仍是可编辑源，预览与 MP4 导出走同一套**随机访问**场景渲染，全片强制 **60 fps**。时间轴可拖片段、拉左右缘改起止（100ms 步进、后续动作连锁 ripple）、速度/循环/逐帧步进；`retime` 把「源参数 1×」映射到拉长后的播放，弹簧与按压采样一并重映射。场景契约是 `publishScene({ seek, timeline, … })`：`seek(time)` 必须任意顺序可复现姿态，禁止增量物理、独立定时器、CSS animation、未播种随机。自带 `projects/cards`（卡片→详情）与 `projects/toggle`；`pnpm check` 做边界帧与 A→B→A 像素比对；导出写 `.mp4.json` 侧车（配置、实际区间、SHA-256）。在线编辑器：[vanechkq.com/editor](https://vanechkq.com/editor)。不是 AE，也不是营销片工具；面向可脚本化的界面动效验收。

**何时用。** 要把一段 UI 动效做成可重定时、可回归检查、可导出 60fps 证据的工程，而不是只靠录屏口述。

**可带走的一点。** 动效验收用 **`seek(seconds)` 纯函数姿态**，不要靠「从 0 播到现在」的累积状态——否则重定时和抽帧对不上。缓存指纹要包含同域资源字节；缺 `cacheInputs` 时宁愿整份 config 哈希，也不要静默脏帧。
