# 动效简报 · 2026-09-18

窗口里两份可带走的：Emil 新加的 `mobile-native`（先把手机端平台层修干净，动效才不「像网页」），以及 `motion-ui-skill` 扩到 339 组件后仍值得盯的弹簧 token 层。

### [emilkowalski · mobile-native](https://github.com/emilkowalski/skills/tree/main/skills/mobile-native)

**类型：** skill / 设计哲学

**是什么。** 9 月 15 日 Emil Kowalski 的 `emilkowalski/skills` 合集新增 `/mobile-native`：专门把「浏览器里的网站」改成「装在手机上的产品」。它不管曲线与编排（那是 `/animate`），只管平台层：粘住的 `:hover`、点击灰闪、`100vh` 被地址栏坑、输入框小于 16px 导致整页缩放、点按滞后、下拉刷新抢走滚动、刘海安全区、长按选中按钮文字、轮播抢垂直滚动、状态栏颜色与主题不一致。每条都给能力查询 / 元标签 / 一两行 CSS，并强调 Chrome 设备模拟器复现不了这些症状——真机才是验收标准。装法：`npx skills@latest add emilkowalski/skills`。

**何时用。** Web / PWA 在真机上「能点但别扭」、抽屉与底部栏感觉漂、或动效本身没问题却整体像嵌在 Safari 里的文档时。

**可带走的一点。** **悬停样式一律包进 `@media (hover: hover) and (pointer: fine)`；按压缩反馈写在 `:active` / `pointerdown`，别等 `click`。** 输入框在粗指针设备上至少 `font-size: 16px`，禁止用 `user-scalable=no` 堵缩放。App shell 用 `100dvh`，营销首屏用 `100svh`。

### [motion-ui-skill · 扩到 339（Craft 层）](https://github.com/Rkj0123/motion-ui-skill)

**类型：** skill / 组件（增量）

**是什么。** 9 月 17 日 `Rkj0123/motion-ui-skill` 合并大更新：在原先 Motion 原语 / AI 对话表面 / Blocks 之上，再塞进约 209 个 Craft & Surface（3D 按钮、设备框、渐变背景、社交卡片等），总量到 339，版本标到 2.0。共享地基没变：`lib/ease.ts` 仍是命名缓动（`EASE_OUT` `[0.16,1,0.3,1]` 等）与分场景弹簧（`SPRING_PRESS` 500/30/0.6、`SPRING_PANEL`、`SPRING_LAYOUT`、`SPRING_GLIDE`…），六种 `stylePreset`，组件走 `useReducedMotion` 与 hover 能力探测。装法：`npx skills add Rkj0123/motion-ui-skill --skill motion-ui`，或用仓库里的 `scripts/install-component.py <slug>` 按需拷贝。

**何时用。** 要可运行的 React 微交互样板，或直接复用一套已命名弹簧表时；不要把整包 Craft 当设计系统灌进产品。

**可带走的一点。** **只带走 `lib/ease.ts` 与一两个场景组件。** Craft 层大多是展示向 mockup/背景，偏「组件合集」；按压用 `SPRING_PRESS`，面板用 `SPRING_PANEL`，跟手装饰用 `SPRING_MOUSE`，滑块用无回弹的 `SPRING_GLIDE`——别让所有交互共用一个 bounce。
