# 2026-11-02 动效日报

周末档五件：Emil 周末推的「先删再改再查性能」工作流正中的 `/improve-animations`；配套的「该动哪、不该动哪」机会扫描；把参考站/录屏逆向成可验收 `motion-spec` 的取证 skill；133 种可点可抄的 UI 名词表；以及 audit-first 的 React Native 动效 skill 包。

### [improve-animations · 只规划、不改码的全库动效审计](https://github.com/emilkowalski/skills/tree/main/skills/improve-animations)

**类型：** skill

**是什么。** Emil Kowalski 技能库里的顾问型 skill（[SKILL.md](https://github.com/emilkowalski/skills/blob/main/skills/improve-animations/SKILL.md) + [AUDIT.md](https://github.com/emilkowalski/skills/blob/main/skills/improve-animations/AUDIT.md)）。2026-10-31 他在 X 推了周末流水线：`/remove-animations → /improve-animations → /animation-performance`（[帖子](https://x.com/emilkowalski/status/2116583281332503038)）。本 skill **只读源码**：先 recon 栈/token/频率图，再按八类并行审计（目的与频率、缓动与时长、物理性与原点、可中断、性能、无障碍、一致性、漏掉的机会），把发现排成杠杆表后，才把选中项写成可交给便宜模型执行的自包含 `plans/`。硬规则：不改业务代码、不装依赖、计划里必须写出精确 `cubic-bezier`/时长/文件路径与现有片段。`AUDIT.md` 写死了目标值，例如 UI 入口用强 ease-out `cubic-bezier(0.23, 1, 0.32, 1)`、UI 动效尽量 &lt;300ms、禁止 `scale(0)`、键盘/100+次/天动作直接删动画。

**何时用。** 现成产品动效又多又乱，想先出一张「改什么最值」的路线图，而不是让 agent 当场乱改；或配合已经用过的 `remove-animations` / `animation-performance` 做周末三连。

**可带走的一点。** 审计结果里最高杠杆往往是删除：高频与键盘触发的动画先砍，再谈换缓动。

### [find-animation-opportunities · 找该动的、拒不该动的](https://github.com/emilkowalski/skills/tree/main/skills/find-animation-opportunities)

**类型：** skill

**是什么。** 同一仓库的互补 skill（[SKILL.md](https://github.com/emilkowalski/skills/blob/main/skills/find-animation-opportunities/SKILL.md)）：只搜索「现在没动、但值得动」的缝，并强制输出「故意否决」列表。四道闸：频率 → 目的（反馈 / 空间连续 / 状态说明 / 防跳变 / 解释 / 仅稀有场景的 delight）→ 能否压进时长预算 → 会不会妨碍读数据或干活。猎场覆盖无按压反馈、瞬切状态、与触发器脱节的面板、列表错峰、手势无物理、以及首次成功等 delight 预算。建议里必须带精确曲线与时长，并要求 `@media (hover: hover) and (pointer: fine)` 与 reduced-motion。全应用最多 5–7 条；全否决也算合格结果。

**何时用。** 「让界面更活一点」但怕 AI 到处加 fade；或审计之后想补少数高杠杆入口，而不是修已有烂动画（那是 `improve-animations` / `review-animations`）。

**可带走的一点。** 报告必须含 Rejected 节：例如命令面板开合因「键盘、100+/天」直接否决——这比列一长串机会更有用。

### [reverse-motion-skill · 参考站/录屏 → 可验收动效规格](https://github.com/PlevanTem/reverse-motion-skill)

**类型：** skill

**是什么。** 2026-10-31 左右公开的 Agent 工作流（中英 README + [SKILL.md](https://github.com/PlevanTem/reverse-motion-skill/blob/main/SKILL.md)）。目标不是自动抓取器，而是引导 agent：在授权范围内交叉取证（`getAnimations()` / 可访问样式、库实例、真实交互探测、视频关键帧测量），输出 `motion-spec.md`——每条含名称、用途、实现（触发、状态、时序、空间、动力学、中断）、参考依据；覆盖清单区分已检查 / 不可达 / 未检查；未知标 `unknown`，不编造缓动。`references/capture.md` 按「未触发 / 进行中 / 已结束可重现 / 不可重现 / 仅视频」分策略；`references/spec.md` 把验收写成待执行对照，而不是假装已还原。安装：`npx skills add PlevanTem/reverse-motion-skill`。

**何时用。** 要从竞品站、录屏或设计参考迁移动效，又需要可交给实现与 QA 的合同，而不是「看起来差不多」的口头描述。

**可带走的一点。** 取不到参数就写缺口，不要从终态脑补唯一曲线——部分规格 + 待补证据，比假完整更可验收。

### [ui-motion-library · 133 种可点可抄的界面动效名词表](https://github.com/ljun56617-art/ui-motion-library)

**类型：** 组件 / 工具

**是什么。** 2026-11-01 上线的纯 HTML/CSS/JS 实验室：按钮、弹窗、动效、表单、加载、卡片共 133 项，本地打开 `index.html` 才能看到动效。每项有中英名、使用场景、关键参数，以及 `snippets/` 单文件（注释里带「一句话提示词」给 AI）。例如长按确认：按住时 `scaleX` 用 1.2s linear 填满，中途松手以 0.25s ease-out 退回且不执行——和 Emil 审计里「破坏性操作用 hold」同一思路。`catalog.md` 给 agent 检索；改 `src/pages/` 后 `python src/build.py` 重生页面与片段。颜色全是 CSS 变量，移植时映射到自家 token。

**何时用。** 非工程师要跟 AI 对齐「我说的是哪种交互」；或实现前先点一遍真实控件，再让 agent 只读对应 snippet。

**可带走的一点。** 让 AI 先搜 `catalog.md` 再读单个 snippet，不要丢整页大 HTML——提示词里的时长是建议值，可按产品改。

### [react-native-motion-skills · 先审计再动刀的 RN 动效包](https://github.com/Chandravardhan8998/react-native-motion-skills)

**类型：** skill

**是什么。** 2026-10-31 左右的 Codex/Agent skill 包（`.agents/skills/`）：`$rn-motion-audit` 只读可行性扫描 → `$rn-premium-motion` 统筹刷新，另有 tokens、微交互、状态反馈、导航、手势、滚动、表单、图表、质量门等。明确 **不** 自动升级 RN/Reanimated、不写死某品牌皮肤；Reanimated 4 / New Architecture / shared-element 的风险写进 README。`$rn-motion-tokens` 建议语义档：press 90–150ms、小反馈 160–260ms、中等过渡 240–400ms，以及 snappy/settle/soft 弹簧，并强制 reduced-motion 等价（透明度或静帧），禁止全局覆盖系统设置。安装用 `node tooling/install.mjs --project …`，同名 skill 跳过不覆盖。

**何时用。** 已有 React Native / Expo 产品要做一轮克制的手感升级，且必须先摸清栈与性能边界。

**可带走的一点。** 先跑 audit（或 `audit.mjs`）再动手；FPS 只认真机测量，skill 文案里的数字不是承诺。
