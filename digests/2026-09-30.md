# 动效简报 · 2026-09-30

本窗口三件事：`genjutsu` 把「先写交互 thesis、再写代码」做成可审计的反廉价感流水线（v4.0 点名 42 种 AI 默认套路，v4.1 再加整站分身编排）；`orchestrator-pipeline` 一键把 Emil 的 Animate 与浏览器证据圈进前端编排；优设猎人则拆了一例带阻尼推挤的 Lightbox。盯着的 Emil skills、AlphaXe、mblode ui-animation、Motion changelog、animations.dev 本窗口没有新的产品级增量。

### [genjutsu](https://github.com/AThevon/genjutsu)

**类型：** skill / 设计哲学

**是什么。** `AThevon/genjutsu`（前身 creative-excellence）是跨 Web / Compose / SwiftUI 的创意编码 skill 包：`cast` 给单次界面动效，`paint` 给视觉体系，9 月 30 日的 **v4.1** 再加 `bunshin` 做整站分身编排。核心习惯是**先提交互 thesis，等人确认再写代码**；preview 门会把缓动曲线画出来、给可重放的试片，而不是只甩一句文案。9 月 28 日的 **v4.0** 新增 `tells` 模块：把模型常写的 42 种廉价默认（假仪表盘、无限脉冲、三等分卡片、未点名的 display 字体、永不停止的装饰循环等）写成可检测条目，并要求 thesis 下挂 `Allowed patterns:`——没点名的套路一律当问题清掉。安装推荐：`npx skills add https://genjutsu.athevon.dev -g`（不要直接 `npx skills add AThevon/genjutsu`，会丢掉内部模块）。站点与 tells 图鉴：https://genjutsu.athevon.dev/

**何时用。** 让 agent 做产品微交互或落地页动效时，要强制「先 thesis、反 AI 默认套路」，或要在 Web/Compose/SwiftUI 之间共用一套时长与降级规则时。

**可带走的一点。** **进场用 ease-out / spring，退场更短且更克制（例如进 300ms、出 200ms 且可只做透明度）；UI 交互别超过 500ms。** 频率越高越短：每天上千次的 hover 用约 100ms；一次性 onboarding 才配得上 600ms+ 编排。永远不要对进场用 ease-in，也不要把元素 `scale` 到 0。

### [Orchestrator Pipeline](https://github.com/klebr55/orchestrator-pipeline-skill)

**类型：** skill

**是什么。** `klebr55/orchestrator-pipeline-skill` 是今天新上的前端编排 skill：一条命令装九件套（编排器 + Taste、MengTo Awwwards craft、**Emil Kowalski Animate**、Vercel Web Design Guidelines、Three.js/R3F、shadcn、Playwright CLI），用来决定**何时叫谁、要带回什么证据**，而不是把特效堆成清单。动效阶段要求给 CSS / GSAP / 组件动效 / R3F 帧循环划清属性所有权，并带上中断、退场与 `prefers-reduced-motion`。安装示例：`npx --yes --package=@klebr55/orchestrator-pipeline-skill orchestrator-pipeline install --agent codex`（可改成 cursor 等）。

**何时用。** Agent 要同时碰视觉方向、组件选型、动效和浏览器验收，又怕「营销站处方」渗进后台产品时。

**可带走的一点。** **按 Animate 的顺序问每一个拟动交互：该不该动 → 目的 → 最便宜的工具 → 中断/退场/减动。** 简单反馈优先 CSS；同一属性不要让 GSAP、React Bits、CSS 和 R3F 抢着写。密集高频产品界面默认克制动效，没有 skill 强迫你上 WebGL 背景。

### [Kobra Lightbox 阻尼推挤](https://www.uisdc.com/hunter/0221685393.html)

**类型：** 设计哲学 / 规范

**是什么。** 优设「细节猎人」1 天前条目：龙爪槐守望者拆解 Kobra 设计系统里的 Lightbox。常规灯箱只是铺半透明遮罩；这里图片向中心放大弹出时，邻近卡片像被物理推开并带轻微压缩形变，关闭时放大图原路缩回，网格带着阻尼回弹归位。位移有动量扩散感——离中心越近形变越大，边缘只做轻移，避免机械式均匀推开。

**何时用。** 做媒体网格 / 作品墙的灯箱或共享元素放大，想让周围内容一起「让路」而不是死板压一层黑罩时。

**可带走的一点。** **邻域响应按距离衰减，不要给所有卡片同一位移；关闭路径要可逆并带阻尼回弹，而不是瞬间复位。** 推挤是解释空间关系的功能性动效，不是装饰粒子。
