# 动效简报 · 2026-10-08

今天五件事。最值得收藏的是 `compose-microinteractions`：一份写得很硬核的 Jetpack Compose 微交互 skill，把「两条弹簧拉出果冻指示条」和「零重组动画」讲到了可以直接抄的程度。`noah-motion` 是中文作者的 8KB 零依赖动画库，弹簧用闭式解，能直接导出成 CSS `linear()`。`ui-motion-skill` 是一个中文动效 skill，自带一份「反廉价自检清单」。`wechat-miniprogram-ui` 是少见的微信小程序动效组件库 + skill，28 个组件统一用 WXS 跟手。最后是 `murmuration`，偏营销站，但它「先找主题的动词，再决定怎么动」的方法值得看。盯着的 Emil skills、Motion、LottieFiles skill、gsap-skills、AlphaXe 本窗口没有新提交；mblode 只给 ui-design 加了压力测试模式（与动效无关）。

### [compose-microinteractions（Jetpack Compose 高级微交互 Skill）](https://github.com/iAmVishal16/compose-microinteractions)

**类型：** skill

**是什么。** `iAmVishal16/compose-microinteractions`（MIT）是作者 SwiftUI 版 `swiftui-microinteractions` 的 Android 对应版，整个 skill 就一份 `SKILL.md`，用 `/compose-microinteractions 一句话描述` 调用，每次产出一个完整可编译的 `.kt` 文件，也支持「edit 某文件」只改指定部分。它给了一张弹簧预设表，全部写成 Compose 的 `dampingRatio` + `stiffness`，并对照 SwiftUI 的叫法（比如 `.snappy` ≈ `spring(0.75f, 700f)`），还专门提醒 SwiftUI 的 `dampingFraction`/`response` 直接照搬会编译失败。性能部分把「零重组」列为第一规则：逐帧变化的值不能在 composable 主体里读，要放进 `offset { }`、`graphicsLayer { }`、`drawBehind { }` 这类布局/绘制阶段的 lambda。另外有触觉反馈分级（tick / selection / medium / heavy）、可拖动数值旋钮（方向锁定、橡皮筋阻力、贴边自动连发、松手回弹）和果冻选中指示条的完整写法。它不是通用动画库，只管 Compose 里的手感型微交互。

**何时用。** 用 Compose 做标签栏、分段控件、计数器、拖拽控件，想要 iOS 那种「有物理感」的反馈，或者要把 SwiftUI 微交互移植到 Android。

**可带走的一点。** **果冻指示条 = 同一个目标、两条不同的弹簧。** 左右两条边都追 `selectedIndex`，一条硬（`0.75f / 700f`）一条软（`0.60f / 190f`）；`left = slot * min(lead, lag)`，宽度按两者差值加一格。两条弹簧不同步时指示条自然被拉长，停稳后缩回一格；再按拉伸量压扁高度 `scaleY = 1 - stretch * 0.14`，看起来就从「橡皮方块」变成「液体」。还有两条：2D 拖拽只用**一个** `Animatable<Offset>`，两个 Float 回弹时会不同步；触觉只在状态真的变了时触发，绝不放进逐帧拖拽循环。

### [noah-motion（闭式弹簧 + 可拖动时间轴的小型动画库）](https://github.com/noahvisualsx/noah-motion)

**类型：** 库

**是什么。** `noahvisualsx/noah-motion` 是一个 TypeScript 写的零依赖动画库，gzip 后约 8KB，README 本身就是中文。它的弹簧不逐帧模拟，而是直接解二阶阻尼振动方程，给任意时间就能拿到精确的位置和速度，欠阻尼、临界、过阻尼三种情况都是精确解。`spring({ duration, bounce })` 返回的函数带 `velocity(t)`、`settle`（多久停稳）和 `toCSS()`，后者直接吐出 CSS `linear(...)` 缓动和时长。`track` 把「在第几秒改去哪个目标」写成剧本，每次改目标都从当下的位置和速度起一条新弹簧并叠加，所以中途改主意也能自然衔接。`noah-motion/dom` 提供 `flip`、`countUp`、`morph`（改按钮内容时宽高弹簧过渡）、`reveal` 等常用网页动效，默认尊重「减少动态效果」设置。另附 21 个演示场景和一个用 Playwright 逐帧截图合成 MP4 的命令行。

**何时用。** 想要弹簧手感但不想引入整个 Motion/GSAP，或者需要同一段动效既在网页实时播放、又能精确导出成视频（产品演示、发布片）。

**可带走的一点。** **把动画写成时间的纯函数**：`render(t)` 只根据 `t` 画画面，不保存上一帧状态。这样拖动、倒放、暂停到任意帧和导出视频都不会出错。另外，`bounce` 取 0 是刚好停住不过冲，0.2–0.4 才是明显回弹，负数会更「黏」地慢慢停住；被打断时把 `velocity` 传给下一条弹簧，衔接才不会断。

### [ui-motion-skill（UI/UX 动效交互 Skill）](https://github.com/c2311395651-stack/ui-motion-skill)

**类型：** skill

**是什么。** `c2311395651-stack/ui-motion-skill`（MIT，v0.3）是一个中文动效 skill，作者说动效库会跟着抖音视频每期更新，安装是 `npx skills add https://github.com/c2311395651-stack/ui-motion-skill`，也可作为 Claude Code 插件装。它要求 AI 先用一句大白话说明打算加哪几个动效、为什么，用户确认后再写代码。内置 6 个动效（变形菜单、卡片展开、点赞爆粒子、提交按钮三连变、果冻开关、长按确认），每个都写了「什么时候用」和「什么时候不用」，比如长按确认只用于删除、注销这类危险操作。`foundations.md` 给出时长分级（小元素 150–250ms、面板 300–450ms、转场 450–600ms、任何动效不超过 700ms）、进场 ease-out / 退场 ease-in、回弹超调不超过 8%、交错间隔 30–60ms。交付前要按 `anti-cheap.md` 逐条自检，动效、视觉、可用性三类都有。默认产出单文件 HTML，参数集中成 CSS 变量。

**何时用。** 用中文跟 agent 协作做 H5、小程序或 App 界面，想让它别「点一下就硬切」，又需要一份它能照着自检的清单。

**可带走的一点。** 直接借它的反廉价清单做交付门槛：**没有 linear、没有硬切；打开和关闭路径一致；可点击元素有按下态（缩放到 0.96–0.98）；不做为了炫而无限循环的装饰动画；大面积模糊控制在 `blur(24px)` 以内；深色界面用深灰 `#0f1013` 而不是纯黑。** 注意一处和 Emil 的原则相反：它的菜单示例从 `scale(0)` 弹出，实际用时建议改成从 0.9–0.95 起步配合透明度，不然会显得「凭空冒出来」。

### [wechat-miniprogram-ui（微信小程序高阶 UI 与质感动效组件库）](https://github.com/Corps-Cy/wechat-miniprogram-ui)

**类型：** 组件 / skill

**是什么。** `Corps-Cy/wechat-miniprogram-ui`（MIT）既是一个 agent skill（`SKILL.md`），也是一套纯原生的小程序组件源码，收录 28 个组件，分四类：凭证卡券弹层、质感微交互、页面布局、触觉手势与提示。每个组件都写清楚了具体参数，比如「照片抽屉贴合：大图 1.08→1 铺满，-22px 咬合推入」「点击翻面凭证：1200px 景深，原地 180° 翻转，转到 90° 时换面」「阻尼弹性抽屉：橡皮筋回弹，LOW / MID / FULL 三段速度吸附」。整套组件共用一套动效基准：减速曲线 `cubic-bezier(0.2, 0.7, 0.2, 1)`、回弹曲线 `cubic-bezier(0.175, 0.885, 0.32, 1.25)`，子元素错开 16–70ms 进场。关键时刻（圆环闭合、刻度卡位、手势吸附、撤销）触发 `wx.vibrateShort({ type: 'light' })`。不需要 TypeScript 或构建步骤。

**何时用。** 做微信小程序里的卡券、核销、抽屉、跟手卡片这类交互，想要比默认组件更有质感，又不想自己从零摸 WXS 性能。

**可带走的一点。** **小程序里所有跟手拖拽一律放到 WXS 在视图层算，不走 `setData`。** 3D 倾斜、阻尼抽屉、滑卡这类高频手势，每帧跨线程 `setData` 一定会掉帧抖动；这是小程序动效能不能「丝滑」的分水岭。

### [Murmuration（让网站按主题本身的「动词」来动）](https://github.com/aniketshukla1/murmuration)

**类型：** skill / 设计哲学

**是什么。** `aniketshukla1/murmuration`（MIT）是一个做「电影感、动效丰富」网站的 agent skill，纯 HTML/CSS/JS，不需要框架和构建。它针对的问题很明确：让 AI 做「有动画的落地页」，每次都是渐变色块、漂浮粒子、点阵地球和倾斜卡片。它的做法是先读主题找「动词」（烘焙机在转、账本在平衡、房子在搭起来），再选一个招牌技法加两到四个安静的辅助动作。动手前必须写一份动效简报：招牌是什么、为什么来自这个主题、强度 1–10、滚动和指针各驱动什么、减少动态效果时的静止画面。作者用 6 个不同主题在隔离会话里测试，产出的动效互不相同，并附评分器和浏览器修复记录。它偏营销站和 3D，不是产品界面 skill。

**何时用。** 要做发布页、品牌站、作品集这类「页面本身就是作品」的场景，又想避开 AI 那一套千篇一律的动画。

**可带走的一点。** 两条可以搬到任何项目的规则。第一，**简报测试：如果这几行动效描述原封不动放到竞品网站上也成立，就是太泛，重写。** 第二，按强度分档定时长并写成 token：安静档（1–4）悬停/按压 150–200ms、进场 300–400ms、交错 40ms 且最多 8 个；任何档位退出都不超过约 250ms，正文永远不做视差，磁吸/弹性效果每屏最多一两个。
