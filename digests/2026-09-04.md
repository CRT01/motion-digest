# 动效简报 · 2026-09-04

窗口里四份新东西：一份专审「已经上线的动效」的审计 skill、一份落地页动效门禁、一份用设计系统 token 写可交付 motion spec 的 skill，以及一份把落地页动效写成「分幕脚本」的工程清单。

### [Motion Audit Toolkit](https://github.com/Jannat63/Motion-Audit-Toolkit---A-Claude-Skill-for-Auditing-Shipped-Animations)

**类型：** skill

**是什么。** 9 月 4 日新开的 Claude Skill，专审**已经上线**的 CSS/JS 动效，不做生成、不评缓动美感。装法：把仓库拷进 `~/.claude/skills/motion-audit-toolkit`，然后跑 `python3 scripts/motion_scan.py <path>`（纯标准库正则，无 pip）。扫描 `.css`/`.scss`/`.js`/`.jsx`/`.ts`/`.tsx`/`.vue`，按三条事实轴出报告：① 性能——属性是不是在触发 layout（`width`/`height`/`top`/`left`/`margin` 等），并给出 GPU 安全替换（通常是 `transform`）；② 无障碍——有多少「含动画的文件」完全没有 `prefers-reduced-motion` 覆盖，用「N of M」说话，而不是笼统说「加过 media query」；③ 时长一致性——同目的交互（hover、模态入场等）是否散落在完全不同的毫秒数上。它明确不做缓动曲线品味（交给 `easingwizard-claude-plugin`）、不做「缺什么动效 / AI 廉价感」缺口分析（交给 `kylezantos/design-motion-principles` 的 Audit）。局限也写清楚：不解析 Framer Motion / GSAP 的 JS API，只抓 CSS 形状的声明和 Tailwind `transition-*`/`duration-*`。

**何时用。** 代码库里已经堆了一批动效，想在性能复盘前快速回答「有没有 jank、reduced-motion 是不是假覆盖、时长有没有各写各的」。

**可带走的一点。** 报告固定顺序：性能 → 无障碍 → 一致性；干净的代码库就写「干净」，不要硬凑 finding。`transition: left` 换成 `translateX`，`transition: width` 的揭示常换成带 `transform-origin` 的 `scaleX`。时长散落时再建议小 token 刻度，例如 `--duration-fast: 150ms` / `--duration-base: 250ms` / `--duration-slow: 400ms`——同类别里大家都在 250–350ms 就不必折腾。

### [lp-motion-craft（Riyoway/lp-craft）](https://github.com/Riyoway/lp-craft/tree/main/skills/lp-motion-craft)

**类型：** skill

**是什么。** 9 月 3 日开源的落地页 skill 包里的动效子 skill：给软件/工具落地页加**有目的、可性能、可降级**的动效。装：`npx skills@latest add Riyoway/lp-craft -g --agent '*' --skill lp-motion-craft --copy -y`。每个动画必须挂一个命名目的：Feedback / Spatial consistency / State indication / Preventing a jarring change / Explanation / Delight（极少、仅首次）。软件 LP 最高价值通常是 **Explanation**——把产品核心工作流演出来，而不是到处 fade。工具链从便宜到贵：CSS transition → `@starting-style` → CSS animation → WAAPI → 只有手势/可打断物理交互才上 Motion/spring。「为一个 fade 装动效框架」直接禁止。

**何时用。** 在做产品落地页、上传/分享类工作流演示、按钮反馈与少量滚动揭示时。

**可带走的一点。** 共享 token：`--ease-out: cubic-bezier(0.23, 1, 0.32, 1)`（入/出场）、`--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1)`（已在屏上的移动）、`--ease-drawer: cubic-bezier(0.32, 0.72, 0, 1)`。UI 交互一般小于 300ms；禁用入场 `ease-in`、禁用 `transition: all`、禁用 `scale(0)`（从约 `.95` + opacity 起步）。文件传输解释范式：设备与目标静止，只 `transform` 移动文件 token；reduced-motion 下保留透明度/颜色反馈，去掉大位移与循环旅行。

### [motion-specs（Uphold Leaf）](https://github.com/magdaraujo/motion-specs)

**类型：** skill

**是什么。** 9 月 3 日公开的 Claude Skill：把产品意图翻成**可交付工程的 motion spec**，数值只许来自 Uphold Leaf 的 duration/easing token，禁止瞎编 ms/bezier。原则写死：Purposeful、Non-obstructive、Feedback、Fast but readable、Performance is not optional。缓动分 Standard / Expressive 两套，并带 decelerate（入场）与 accelerate（出场）；时长从 `$motion-duration-micro1`（50ms）到 `long4`（1000ms）分档。强制「编舞检查」先行：方向、重叠还是串行、触发、循环间隔没有安全默认值——缺什么就用问答工具问完再写表，禁止「假设 X，下面是 spec」。输出是带 From→To 的属性表，多元素时必须写清 delay/起点锚点。React Native 风险单独 flag：`transform`/`opacity` 安全，其它属性提示可能要 Reanimated。

**何时用。** 有（或想抄）设计系统 motion token 时写交接规格；或要对照 token 批判「太 indefinite 的动效需求」。非 Uphold 团队也可当「token 驱动 handoff」模板，但表内数值是 Leaf 的，不要直接当通用真理拷贝。

**可带走的一点。** 默认用 Standard；只有明确的高光/庆祝才用 Expressive，并在 spec 里写理由。出场加速、入场减速。不要把「illustrative example」当实现稿——缺布局偏移就写「confirm exact offset with design/Figma」，不要填一个好听的 px。

### [gh-pages-landing · 动效编舞](https://github.com/yancongya/gh-pages-landing)

**类型：** skill / 规范

**是什么。** 9 月 3 日出现的 GitHub Pages 落地页 skill，Stage D 把动效当成叙事第四维：先写分幕脚本再写代码。意图只认四类——orient / reveal / compare / confirm；说不出意图的动画当装饰砍掉。每页只许一个 signature moment（访客关掉页面还能记住的那一幕），并用「隐喻 / 时机 / 不可截图性 / 成本」四问定案。技术选型：先 CSS，不够再 GSAP+ScrollTrigger，极少 Three.js。参考文件 `references/motion-choreography.md` 用中文写满工程硬坑。

**何时用。** 给仓库/产品做营销落地页、滚动叙事或 pin 场景，需要在开写 GSAP 之前把意图与降级写死。

**可带走的一点。** 分幕表每行必须有「降级」列：`prefers-reduced-motion`（时长/位移归零、内容仍在）、无 JS（CSS 保留、库驱动要有静态等价）、移动端 `matchMedia`（重动效在 ≤768px 降为淡入或静态）。GSAP 实战坑：`y: 80` 是相对位移不是绝对坐标；`gsap.set` 不能写在 `defer` CDN 之前；Lenis 接管后要用 `window.__lenis.scrollTo`；pin 的目标必须自带背景，否则下层会透出来。
